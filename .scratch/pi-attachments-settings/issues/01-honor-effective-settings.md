**Blocked by:** None (can start immediately).

**Status:** implemented — effective settings, recovery, and the pre-clear Send gate pass on unmodified Pi with both editors. Ticket 07 records full-extension runtime checks and the remaining physical-terminal acceptance.

**Specification:** [Pi Attachments](../../../docs/specs/pi-attachments.md), including its applicable architecture decisions.

**Integration:** Tickets 01–05 remove coupled host contracts in one integration checkout. Focused checks accompany each slice; complete unmodified-Pi startup and regression acceptance belong to ticket 07. Do not invent host shims to make intermediate checks pass.

**Current implementation and verification (2026-10-14):** `registerImages(...)` exposes `prepare(request, ctx)` to the package's pre-clear Send gate and uses the same operation from Pi's public input event. It freezes session, working directory, text, route, and supplied images before awaiting recovery and image work. The editor submits the frozen request through the existing native callback. Same-route requests wait in Send order; the public input path preserves earlier transformations and supplied images, and reports preparation failures with `handled` before queue acceptance. Current image blocking does not skip preparation. Resize settings apply before queueing, and Pi applies final blocking.

Recovery has two necessary checkpoints: the exact requesting draft before native clearing, and the public input after earlier handlers may transform text or supply images. Historical recovery metadata remains readable without requiring native submission identity fields. A retained text reference also needs the first asynchronous recovery write and content-type check before clearing. Typing while this work is pending preserves the edited draft. Plain text with no attachment work or same-route predecessor retains native immediate Send behavior.

Concurrent image preparation shares in-flight work by retained path, effective `images.autoResize`, and model resize options. Completed images are weakly cached so a long session does not retain every prepared base64 payload. Collected content is read again from the retained snapshot; it never recaptures the source. Failed work can be retried, abort releases the cache, and returned images do not expose mutable cached objects. No cache entry carries submission identity.
