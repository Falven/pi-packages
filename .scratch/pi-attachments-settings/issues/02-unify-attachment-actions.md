# 02: Configure attachment shortcuts through Pi's existing binding file

**What to build:** Attach… offers a file path or literal entered text. Users configure it and Manage attachments… by editing Pi's existing binding file and running /reload, while command access remains available.

**Blocked by:** None (can start immediately).

**Status:** implemented — file-based bindings, native shortcut dispatch, command access, source flows, and the command hint pass the integrated public-host checks. Both editors also pass the fresh Pi 1.1.0 and 1.2.0 executable checks recorded in ticket 07; physical terminal gestures remain unverified.

**Specification:** [Pi Attachments](../../../docs/specs/pi-attachments.md), including its applicable architecture decisions.

- [x] Resolve only extension.attachments.attach and extension.attachments.manage from keybindings.json in Pi's active agent directory. An absent entry uses Ctrl+Alt+F or Ctrl+Alt+A respectively; a configured key or list replaces the default, and an empty list disables the shortcut.
- [x] Validate the package's entries and report malformed configuration. Preserve already-saved attachment bindings, unrelated entries, and native clipboard configuration. Reread bindings on /reload without leaving stale registrations or handlers.
- [x] Register concrete keys, descriptions, and handlers through pi.registerShortcut(). Remove dependencies on locally added named-action and action-key lookup APIs. The package owns resolution of its two entries; Pi handles registered shortcuts. This is the accepted community fallback, not official named-action registration.
- [x] Preserve actual native conflict dispatch and verify it with remapped native actions and competing extension shortcuts. Supply descriptions for Pi's read-only /hotkeys display. The widget shows a compact Manage attachments hint using /attachments; /hotkeys remains the source for effective shortcuts. Verify that remapping, disabling, conflicts, and reload cannot make that command hint inaccurate; a handled key performs only one action.
- [x] Preserve Attach… with File path… selected by default and Create from text… secondary. Detect content type automatically, accept established path forms without shell evaluation, and capture literal entered text exactly, including path-looking strings, empty content, and final newlines.
- [x] Cancelling either source dialog closes the flow without changing the draft. Preserve caret or selection insertion, native clipboard precedence and dispatch, ordinary paste classification, and retained recovery.
- [x] Keep /attach, /attachments, /attachments-recover, /attachments-cleanup, and /paste-recover usable, including when shortcuts are disabled. Retire /attach-file, /attach-text, /paste-inline, Ctrl+Alt+T, and Ctrl+Alt+V without aliases.
- [x] Add no keybinding editing menu, second binding file, separate keybinding manager, shared configuration framework, or configurable action beyond the two accepted actions.
- [x] Adapt existing checks for absent, single, multiple, empty, and malformed entries; alternate active agent directories; reload; native conflicts; /hotkeys; hints; commands; source flows; and cancellation. Verify actual runtime dispatch on unmodified Pi during ticket 07, without mocking the removed action APIs.

**Integration:** Use the shared contract-removal checkout described in ticket 01. Full-extension acceptance and installation restoration belong to ticket 07.

**Implementation verification (2026-10-14):** Thirteen checks exercise the package's real shortcut registration through unmodified Pi 1.0.2's interactive editor and resource lifecycle. They cover default bindings, string and list replacements, alternate active agent directories, explicit unbinding, file edits applied by `/reload`, removal of stale registrations, malformed entries and files, UTF-8 BOM handling, preservation of unrelated entries, and Pi's read-only `/hotkeys`. Invalid entries disable that action with a visible error; an unreadable or malformed file disables both shortcuts with a visible error. Commands remain registered. `node --test packages/pi-attachments/test/shortcuts.test.mjs` passes. These initial checks loaded only the action registration. The later integrated suite and fresh executable checks in ticket 07 exercise the complete extension and its source flows.

Native conflict dispatch was observed directly: remapping reserved `app.clear` to the Attach key makes Pi skip that attachment shortcut; a Manage binding can override nonreserved `tui.editor.deleteCharBackward`; a later competing extension registration wins. Each handled key invoked one action, and `/hotkeys` showed only the native winner. The package does not copy Pi's conflict table or inspect its private shortcut state.

**Accepted hint decision:** Released Pi exposes concrete registration but no public query for the final accepted extension shortcuts. `getCommands()` returns command information, and the supplied keybinding manager describes native bindings; neither exposes the native shortcut winners used by `/hotkeys`. Showing configured keys as accepted shortcuts would be inaccurate after the observed conflicts. The widget now uses the accepted `/attachments` command hint, with `/hotkeys` for effective shortcuts. The obsolete `getActionKeys()` call is removed without copying conflict rules or inspecting private shortcut state.

**Hint verification (2026-10-14):** The native preview check first failed with `getActionKeys is not a function`. Six focused checks now pass through the real image widget, shortcut registration, native editor, and resource lifecycle on unmodified Pi 1.0.2. They verify the compact command hint, unchanged retained image and draft, remapping, unbinding, reserved native conflicts, competing extension ownership, `/hotkeys`, and reload with the existing image. Together with the shortcut checks, `node --test packages/pi-attachments/test/hint.test.mjs packages/pi-attachments/test/shortcuts.test.mjs` passes all 19 checks. Scoped TypeScript, lint, formatting, and diff checks pass. The composer preview expectation is updated to the command hint; the later full-extension and composer checks pass at the public host boundary. Ticket 07 records the restored and official executable checks. Physical terminal behavior was not observed.

**Historical verification (2026-10-14):** The previous checks exercised source flows, cancellation, paste, recovery, retired commands, and modified-host action configuration through /settings. Attachment, composer, chat, and 31 composer viewport cases passed, with type, lint, and format checks. The modified host's configuration menu and action APIs have been removed; those historical results do not establish file-based remapping, reload, conflicts, or hints on unmodified Pi. Physical clipboard gestures and terminal rendering were not observed.
