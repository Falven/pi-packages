- [ ] Keep skill interpretation, compact presentation, temporary reveal, and the native adapter inside `pi-skill-references`. - [ ] Render one normal user message containing the available reference-bearing request. Cover native leading expansion, inline and multi-skill package expansion, repeated references, aliases, and skill-only invocations. Show no generated body, purple skill row, placeholder, badge, or permanent expansion control during ordinary chat.
- [ ] Preserve the recorded request when available. - [ ] Preserve retained-source Find where available. A match inside instructions reveals only its skill occurrence's saved content at the owning user message, without a purple card. Matches in ordinary request text or references do not reveal unrelated instructions. Navigation away, loss of the selected match, and closing Find restore compact presentation.
- [ ] Keep duplicate messages and repeated invocations distinct through source identity and match ranges. Use recorded instructions even if the current skill was changed or removed; no file reload, tool execution, or model request is caused by rendering or Find. Respect the active branch and available pre-compaction source without inventing omitted content.

Check required capabilities; cover history reconstruction before session-start callbacks, reload, session replacement, branch changes, and extension disabling. Clear stale reveal state and restore only still-owned hooks. On adapter installation failure, release partial integration, report the limitation, and preserve native operation and invocation.
- [ ] Leave Pi source and installed packages untouched. Add no fork, persistent global hooks, private message-delivery changes, duplicate conversation storage, new presentation schema, setting, command, dependency, or shared runtime framework.
- [ ] Leave HTML exports, JSON/RPC and other machine-readable outputs, and headless behavior unchanged. Validate the original retained source and actual provider payload, not merely a compact rendered string or instruction count.
- [ ] Verify the complete behavior through the approved real-host seam, preserving existing completion and invocation coverage and using chat's source-Find/reconstruction cases as prior art.
