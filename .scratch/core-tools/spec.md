## Problem Statement

Matching tool declarations currently conceal different behavior. The core toolset coerces some invalid arguments, stops an awaited command when its execution cell is terminated, treats an explicit shell path differently, and omits parts of the reference's JavaScript failure result. These differences change what the agent can do and what information it receives for its next decision.

The same patch can also leave different files behind. Deleting a file and then its symlink currently removes both in Pi. The reference deletes the file, fails the now-dangling symlink deletion, and leaves the link. An image requested at original detail can arrive resized with automatic provider detail. More precise instructions cannot recover image evidence already changed by the implementation.

Pi's built-in tools give the agent a different interface for commands, file changes, and images from the fixed tool contract the user wants to use. Tool names alone do not account for the difference. Declarations, instructions, argument encoding, execution, continuation, errors, output limits, and the results sent back to the model all affect how the agent works.

The user needs the selected contract through the existing extension without any Pi modification. Public dispatch, permission checks, explicit tool selection, retained history, and independently installed extensions must keep working. Core-tool image preparation must follow the reference's rules even when Pi's automatic resize preference would produce another image. Image blocking remains effective.

The user also needs verifiable comparisons. Similar answers or a successful demonstration do not establish that the model received equivalent tools or that tool execution behaved the same way.

The toolset must describe actual operations separately from the calls that collect their results. Package-specific chat decoding couples independent extensions and turns collection or empty execution receipts into visible actions. The neutral activity contract supplies semantic facts usable by any consumer while preserving execution and model-facing results.

## Solution

Correct the six selected differences against the captured reference behavior:

1. End an execution cell's program without implicitly killing a command that has already started; preserve later process interruption and session cleanup.
2. Validate original arguments before Pi can coerce them. Match the reference's field-specific types, nulls, defaults, numeric ranges, and ignored unknown keys while keeping the frozen declarations unchanged.
3. Select an installed shell by the supplied shell kind, including fallback and the treatment of valid custom paths. Keep Pi's configured shell and command prefix when no shell argument is supplied.
4. Return the native failure status, timing, ordered output parts, and genuine source error information while preserving actual child outcomes.
5. Match ordered patch effects: retain earlier deletions, fail a later now-dangling symlink deletion, leave that symlink, and report failed and unattempted changes accurately.
6. Own core-tool image preparation in this extension. Preserve requested detail, match native image limits and encoding behavior, and deliver the correct bytes and metadata through public hooks without restoring removed images.

Keep whole-patch validation and the existing public file mutation queues. At application time, reread each update's source and recompute its replacement before writing, so operations compose in order. Capture before/after facts from the contents each operation actually encounters. A later read or match failure preserves earlier changes and reports the current operation as failed and later operations as unattempted.

Keep the self-contained Pi extension package `pi-codex-tools`. It supplies the core toolset through two direct model tools, `functions.exec` and `functions.wait`. JavaScript executed by `functions.exec` can call four selected tools: `exec_command`, `write_stdin`, `apply_patch`, and `view_image`.

Commands cover local execution, text reading, searching, and listing. Patches cover file creation and modification, including moves and deletion. The image tool and image output helper cover local image inspection. The package replaces equivalent stock built-in capabilities without taking over unrelated extension tools or the rest of the agent interface.

The captured contract remains the declaration baseline; the six behavior corrections use the version-associated reference identified below. Pi's public dispatch, permissions, image blocking, result edits, and normal extension lifecycle remain authoritative. The extension owns final image preparation through existing public APIs. Pi still processes real image blocks before the finalized-message hook; the successful PNG probe does not establish a complete processing bypass or equality for every earlier event and display consumer. The package owns continuing cells and records their activity through public custom entries. Native nested-call identifiers, native attribution after a yield, and notification transport and timing remain separate accepted host differences; package-owned identifiers do not repair them.

Verification uses the existing real Pi host with controlled provider responses. It observes the outgoing model request, executes the requested tools against real temporary resources, and examines every result and the next outgoing request. Reuse the existing differential runner for identical tasks against the reference, including filesystem state, process outcomes, and image bytes. Matched live-model trials then measure behavior under equivalent task conditions. Publish new captures to the existing local Phoenix project and verify the stored data; retain earlier observations under their original run identities.

This revision constructs the documented activity data format inside the existing package, without a shared contract package or dependency on a consumer. It preserves stable operation identity, effective inputs, individual outcomes, bounded applicable output, and per-file changes. Raw script results and errors remain in model results and retained source without becoming new work. A command can have several meaningful submitted actions. Input/collection calls produce no action, including when they fail. Exact Ctrl+C input can interrupt a non-terminal process, matching the pinned app build. No consumer name, renderer, summary, or layout belongs in this package.

Command output and process outcomes update their origin through existing process events, independently of model collection or custom renderer creation. Pi result details, event bus, and retained custom entries carry the same validated contract. Original source, result hooks, native image placement, and standalone tool rendering remain intact. Add no polling, extra calls, alerts, settings, or unsolicited turns. The [generic activity specification](../../docs/specs/tool-activity.md) governs the delta.

## Implementation Decisions

1. **Scope and target.** Deliver one package for the measured macOS arm64 environment and the configured Responses-compatible provider path. Use normal package discovery, public extension registration, public provider composition, and public lifecycle events. Pi must remain unchanged under every circumstance: do not edit its source or installed packages, patch private runtime behavior, change global settings around a call, fork it, or change its version requirements to obtain new host behavior. Add no platform, provider, or version guard framework. No unresolved target authorizes a Pi change. Preserve unrelated integrations, including the existing chat package boundary.

2. **Frozen baseline.** Retain captured declaration baseline `local-tools-reference-20261013`, identified by canonical source SHA-256 `c96638241baa0167c3603823374d67a616a4d4df5142496a1d13971ece498843`. The canonical encoding is sorted-key, compact UTF-8 JSON. This checksum identifies the complete source capture, not an implemented or validated scoped contract. The six behavior corrections use the installed reference captured as `0.163.0-alpha.10.2` and version-associated source commit `4ebc485ca321243727539187169425fcf972f2c4`. This association is not proof of a reproducible build. Preserve the scoped declarations and historical captures; new runs record their own source and binary identities. Updates are deliberate package changes, with no runtime synchronization, alternative profiles, or installed-application dependency.

3. **Two direct tools.** The outgoing selected tool surface exposes `functions.exec` and `functions.wait` with the captured namespace, input form, descriptions, schemas, required fields, optionality, and constraints. `exec` accepts raw JavaScript with the optional first-line execution pragma; it must not become a model-facing JSON code wrapper. `wait` accepts its captured object schema. Retained core tool guidance is word-for-word from the frozen scoped reference. Remove local lifecycle/image/notification additions and the rewritten notification description. Selection may omit unavailable tool sections and directly dependent helper text but cannot rewrite retained text. Host differences belong in operator documentation. Do not add read-style, batching, or shell-formatting advice; ChatGPT.app/Codex system prompts and other prompts are out of scope. The earlier verbatim-guidance ticket verifies complete actual outgoing declarations.

4. **Four nested tools.** The execution environment exposes `exec_command`, `write_stdin`, `apply_patch`, and `view_image` through its `tools` object. Text reading, searching, and listing use commands. There are no additional read, write, edit, search, list, or alternate-shell aliases. Register the selected operations with Pi so nested calls retain native dispatch. Use public exposure and loadout controls to separate model declarations from callable operations; never confuse a hidden declaration with a permission restriction.

5. **Selection and ownership.** Replace the equivalent stock `bash`, `read`, `edit`, `write`, `grep`, `find`, and `ls` surface only within the user's enabled scope. Explicit Pi selection and exclusions remain authoritative. Do not reactivate excluded registrations to satisfy a hardcoded list. Preserve unrelated tools, their order and model-dependent availability, and extension-owned overrides identified through public provenance. Retained historical calls are not renamed or rewritten. Newly loaded tools apply on the next request after normal loading or reload, including in an existing conversation.

6. **Execution runtime.** Each `exec` evaluates an async JavaScript module in one fresh worker and V8 context with the selected host helpers. It exposes no direct Node, filesystem, network, or console APIs. The selected command and file tools remain the route to host operations; this runtime isolation is not advertised as an operating-system sandbox. Preserve the captured restriction against running an outer `exec` invocation in parallel with other tool invocations; independent nested calls may run concurrently when Pi permits them. The session-owned execution module exposes `start`, `wait`, and `close`. Each cell keeps its worker across yields; waits never create a worker, restart a script, or replay work. Cells transition from running to completed, failed, or terminated, then to collected. Release a settled worker promptly, retaining unread output, the terminal result, and any metadata still needed for pending host-operation cleanup. Script completion discards unawaited JavaScript promises and timers; it does not imply cancellation of already dispatched host operations or independent process sessions.

7. **Retained helpers.** Keep `text`, `image`, `exit`, `store`, `load`, `notify`, `setTimeout`, `clearTimeout`, and `yield_control`. Keep `ALL_TOOLS` as name/description metadata restricted to the selected tools available when the cell starts; recheck current availability at each dispatch. `text` appends output and stringifies non-string values when possible. `notify` uses a public custom message with `triggerTurn: false`, without duplicating its content into ordinary output or starting a turn. This differs from an extra tool-output event: while Pi is streaming, delivery is deferred until its safe turn boundary. `exit` successfully ends the script. Worker-owned timers do not keep an otherwise completed script alive; timer exceptions fail the cell and termination clears callbacks. `yield_control` returns accumulated output while the same execution continues.

   Store serialized values in a bounded session map. Each cell receives one snapshot and tracks only keys it writes; each `load` parses a copy, and a missing key returns `undefined`. Pending writes remain invisible to overlapping cells. Merge changed keys on normal completion, `exit`, and an ordinary script or timer exception. Discard pending writes on termination or cancellation of the initial execution. Session replacement and reload clear all values. A cell must not overwrite unrelated writes committed by another cell. Copy a bounded snapshot at startup; do not add a cross-thread lookup service without measured need.

10. **Command results.** Preserve the command APIs' required `output` and `wall_time_seconds` fields and optional `chunk_id`, `exit_code`, `original_token_count`, and `session_id` fields. 11. **Two kinds of continuation.** Execution cells use unique string identifiers consumed by `wait`; running commands use numeric session identifiers consumed by `write_stdin`. Do not conflate their state or identifiers. Initial execution waits for completion, explicit yielding, or its yield deadline; the deadline returns a running result without cancellation. Waiting returns only output since the last collection and closes a completed cell once. Collection uses a precise sequence cutoff so later output belongs to the next result. Serialize collection for the same cell; different cells remain independent. Waits use worker events, a completion promise, and one deadline timer per active collector, with no periodic polling. Ordinary text does not wake a pending wait; explicit yield, completion, termination, and its deadline do. Concurrent-wait arbitration and caller-only cancellation are accepted package rules until independently observed in the reference. Preserve the declared 10,000 ms wait and 10,000-token defaults. Command polling preserves its own incremental behavior. Do not substitute native line or byte limits for captured token budgets.

12. **Shell selection and context.** Resolve defaults from the owning execution context, not the extension process's startup directory. On the audited platform, discovery considers a matching account shell, PATH, and family fallback locations; the platform fallback is the POSIX shell. Apply this selection even when the supplied file exists, so a custom startup script can be skipped. The supplied path is not a guarantee that its exact file runs. With the argument omitted, retain Pi's configured shell and existing default behavior. Apply the command prefix once, preserve command text, cwd, login and PTY options, inherited environment, managed search path, and fresh session metadata. Select before spawning; do not retry arbitrary launch errors or a command that already began. A missing cwd remains a failure. Publish the actual selected executable in effective inputs. Read settings through Pi's public service.

Processes and cells share asynchronous output storage. Retain small output in memory and spill larger unread output through batched writes to private temporary files. Apply producer backpressure, including worker-to-host credits outside script globals and paused process streams, before queues grow without bound. Preserve ordered text and images, valid decoding, trailing output, byte/line counters, and collection cutoffs. Read only the new ranges needed for the requested output budget, without repeatedly concatenating or rescanning delivered data. Cell completion alone must not kill a command that already returned its own process handle.

Preserve raw argument preparation, validation, blocking hooks, argument mutation, result mutation, and the image contract in decision 17. Return the processed outcome and associate it with the invocation's promise and a package child identifier made from its cell ID and a monotonically increasing counter. Package IDs do not repair those native IDs, native nested history, usage attribution, or late update delivery. 18. **Lifecycle and cancellation.** Live commands, execution cells, timers, and temporary stored values belong to the active extension session. Cells retain the originating tool-call ID and session identity, with cancellation independent of the original prompt. Initial execution cancellation, resource failure, reload, shutdown, quitting, and session replacement retain their existing cleanup guarantees. Reaching a yield deadline or completing an ordinary prompt preserves continuation. Cancelling a later wait ends only that caller's wait and preserves the cell and unread output.

Explicit cell termination ends the coordinating JavaScript program and prevents new dispatch without implicitly killing an already-running command, including one still awaited by that cell. Return only output already accepted for the cell; do not wait for the command to finish or invent a killed-command result. Retain the live process in the session's existing ownership and cleanup registry, with its actual late status and any previously returned process handle. Late callbacks must not append to closed cell output, resume the terminated script, duplicate operation rows, or start another model turn. A terminated or collected cell must not prevent later forced session cleanup from reaching its processes. Verify queued operations and commands that have not started separately against the reference; process survival does not decide whether a queued file mutation may commit. Preserve bounded cleanup, factual incomplete-cleanup reporting, existing store/load semantics, file changes, and retained history. No daemon, process-global survival registry, or live-handle reconstruction is introduced.

## Provider activity contract

The [neutral activity specification](../../docs/specs/tool-activity.md) defines the public consumer boundary. Semantic operations identify their originating call/session, stable order and revision, kind, actual outcome, applicable inputs/output, optional verified counts, and explicit omission. Native result details bind those facts to processed content; live events and retained custom-entry metadata publish incremental updates independently of custom renderers. Image ownership references native result parts without copying bytes.

A valid empty record means the call has no new activity; missing or invalid metadata means generic fallback. Private execution details and journals may continue serving standalone rendering and model replay, but consumers do not decode them. Result consistency checks cover text/content shape and activity facts, with the existing exception for native image conversion and normalization hints. That exception does not establish image fidelity: the current revision must bind activity and retained sources to the final permitted prepared image and verify consumers that observe an earlier result. These checks are not authentication. Removed or invalid metadata never revives discarded output from an earlier journal. Session replacement clears live state; replay uses only reliable active-branch records and never recreates resources.

Settled execution bodies retain the latest eight operations; patch bodies retain the latest sixteen changes. These windows remove body content, never compact operation or file records. The existing presentation helper uses a 16,384-column and byte budget with an omission marker for truncated text. Patch count calculation trims unchanged prefixes and suffixes, then bounds mixed comparison to 100,000 cells and 10,000 combined lines; pure additions and deletions remain exact. Unreadable prior content or a larger mixed comparison omits counts. These limits do not change returned command output collection or file mutation semantics.

Standalone output attribution retains the existing object-identity limit for primitive text and rejection values. The activity protocol does not try to recover that identity: raw script text and errors stay in processed results and retained source, and returning them creates no new operation. Child outcomes remain independent. Neither script values nor native rejection types change for presentation, and matching text alone never assigns ownership.
