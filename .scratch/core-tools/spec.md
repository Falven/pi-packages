## Problem Statement

Pi's built-in tools give the agent a different interface for commands, file changes, and images from the fixed tool contract the user wants to use. Tool names alone do not account for the difference. Declarations, instructions, argument encoding, execution, continuation, errors, output limits, and the results sent back to the model all affect how the agent works.

The user needs a package that provides the selected contract while retaining the configured Pi experience. Replacing tools must preserve effective host settings, native interception, explicit tool selection, retained history, and independently installed extensions. A renamed wrapper around the existing tools would neither reproduce the intended behavior nor automatically preserve every integration.

The user also needs verifiable comparisons. Similar answers or a successful demonstration do not establish that the model received equivalent tools or that tool execution behaved the same way.

The current package leaves execution calls to Pi's generic presentation. Expanded calls expose orchestration JavaScript, transport headers, and escaped results instead of readable operations. Visible activity records repeat execution identifiers and lifecycle events between calls, creating additional activity-group boundaries. An earlier running record can appear interrupted after successful collection because its live cell has been removed. Command progress is not presented in its originating call while output arrives, and the journal renderer can exceed terminal width or split an emoji. These are package presentation defects; repairing the chat package's separate work-folding defect is outside this revision.

## Solution

Create the self-contained Pi extension package `pi-codex-tools`. It supplies the core toolset through two direct model tools, `functions.exec` and `functions.wait`. JavaScript executed by `functions.exec` can call four selected tools: `exec_command`, `write_stdin`, `apply_patch`, and `view_image`.

Commands cover local execution, text reading, searching, and listing. Patches cover file creation and modification, including moves and deletion. The image tool and image output helper cover local image inspection. The package replaces equivalent stock built-in capabilities without taking over unrelated extension tools or the rest of the agent interface.

The captured contract is the baseline for the included tool names, declarations, instructions, arguments, results, and behavior. Pi's effective settings, public dispatch, result processing, and normal extension lifecycle remain authoritative. The package owns continuing cells and records their activity through public custom entries. Native nested-call identifiers, native attribution after a yield, and notification transport and timing are accepted host differences; they are not repaired by package-owned identifiers.

Verification uses the existing real Pi host with controlled provider responses. It observes the outgoing model request, executes the requested tools against real temporary resources, and examines the next outgoing request. Matched live-model trials then measure behavior under equivalent task conditions.

This revision adds native presentation to the existing `exec` and `wait` tools. A compact action summary and status expand into the underlying operations and readable results. Commands show their command, effective working directory, accumulated output, and exit status. Orchestration source and transport metadata remain in retained history. Each operation stays inside the `exec` card that started it, including progress and failures arriving after a yield or during a later prompt. A `wait` card summarizes collection or termination without repeating operation text. Native images appear once in the result that collects them, including a later `wait`; their operation path and status remain in the originating card.

Command output appears live from existing process output events, and process lifecycle events update its status. Display observation is independent of model output collection. Routine activity records remain retained but invisible in the chat view; the latest recorded outcome restores the originating card after reload. Use Pi's public rendering APIs and screen-refresh batching, without polling, extra tool calls, source changes, automatic failure alerts, or unsolicited model turns. Returned results still pass through normal hooks; live output may already have been visible before a later redaction. Extend the approved host verification seam to establish these presentation behaviors without changing the selected agent interface.

## Implementation Decisions

1. **Scope and target.** Deliver one package for the measured macOS arm64 environment and the configured Responses-compatible provider path. Use normal package discovery, public extension registration, public provider composition, and public lifecycle events. Do not modify Pi, install private runtime adapters, or add platform, provider, or version guard frameworks. Preserve the existing boundary that private integration is an exception for the chat package alone.

2. **Frozen baseline.** Use captured baseline `local-tools-reference-20261013`, identified by canonical source SHA-256 `c96638241baa0167c3603823374d67a616a4d4df5142496a1d13971ece498843`. The canonical encoding is sorted-key, compact UTF-8 JSON. This checksum identifies the complete source capture, not an implemented or validated scoped contract. Extract only the included tool declarations and behavior cases; give that scoped fixture its own identity when created. Updates are deliberate package changes, with no runtime synchronization, alternative profiles, or installed-application dependency.

3. **Two direct tools.** The outgoing selected tool surface exposes `functions.exec` and `functions.wait` with the captured namespace, input form, descriptions, schemas, required fields, optionality, and constraints. `exec` accepts raw JavaScript with the optional first-line execution pragma; it must not become a model-facing JSON code wrapper. `wait` accepts its captured object schema. Preserve the included instructions without broad paraphrasing. Remove only the approved out-of-scope tools, helper overloads, metadata, and related explanatory text.

4. **Four nested tools.** The execution environment exposes `exec_command`, `write_stdin`, `apply_patch`, and `view_image` through its `tools` object. Text reading, searching, and listing use commands. There are no additional read, write, edit, search, list, or alternate-shell aliases. Register the selected operations with Pi so nested calls retain native dispatch. Use public exposure and loadout controls to separate model declarations from callable operations; never confuse a hidden declaration with a permission restriction.

5. **Selection and ownership.** Replace the equivalent stock `bash`, `read`, `edit`, `write`, `grep`, `find`, and `ls` surface only within the user's enabled scope. Explicit Pi selection and exclusions remain authoritative. Do not reactivate excluded registrations to satisfy a hardcoded list. Preserve unrelated tools, their order and model-dependent availability, and extension-owned overrides identified through public provenance. Retained historical calls are not renamed or rewritten. Newly loaded tools apply on the next request after normal loading or reload, including in an existing conversation.

6. **Execution runtime.** Each `exec` evaluates an async JavaScript module in one fresh worker and V8 context with the selected host helpers. It exposes no direct Node, filesystem, network, or console APIs. The selected command and file tools remain the route to host operations; this runtime isolation is not advertised as an operating-system sandbox. Preserve the captured restriction against running an outer `exec` invocation in parallel with other tool invocations; independent nested calls may run concurrently when Pi permits them. The session-owned execution module exposes `start`, `wait`, and `close`. Each cell keeps its worker across yields; waits never create a worker, restart a script, or replay work. Cells transition from running to completed, failed, or terminated, then to collected. Release a settled worker promptly, retaining unread output, the terminal result, and any metadata still needed for pending host-operation cleanup. Script completion discards unawaited JavaScript promises and timers; it does not imply cancellation of already dispatched host operations or independent process sessions.

7. **Retained helpers.** Keep `text`, `image`, `exit`, `store`, `load`, `notify`, `setTimeout`, `clearTimeout`, and `yield_control`. Keep `ALL_TOOLS` as name/description metadata restricted to the selected tools available when the cell starts; recheck current availability at each dispatch. `text` appends output and stringifies non-string values when possible. `notify` uses a public custom message with `triggerTurn: false`, without duplicating its content into ordinary output or starting a turn. This differs from an extra tool-output event: while Pi is streaming, delivery is deferred until its safe turn boundary. `exit` successfully ends the script. Worker-owned timers do not keep an otherwise completed script alive; timer exceptions fail the cell and termination clears callbacks. `yield_control` returns accumulated output while the same execution continues.

   Store serialized values in a bounded session map. Each cell receives one snapshot and tracks only keys it writes; each `load` parses a copy, and a missing key returns `undefined`. Pending writes remain invisible to overlapping cells. Merge changed keys on normal completion, `exit`, and an ordinary script or timer exception. Discard pending writes on termination or cancellation of the initial execution. Session replacement and reload clear all values. A cell must not overwrite unrelated writes committed by another cell. Copy a bounded snapshot at startup; do not add a cross-thread lookup service without measured need.

8. **Image helper scope.** Retain data-URL input and the ordinary object form carrying `image_url` and optional `detail`, including the captured ordinary detail variants and explicit-detail override. Exclude public protocol image-content objects, their metadata, audio emission, generated-image emission, and the shared types or forwarding examples needed only by those excluded helpers. Network image URLs are not introduced.

10. **Command results.** Preserve the command APIs' required `output` and `wall_time_seconds` fields and optional `chunk_id`, `exit_code`, `original_token_count`, and `session_id` fields. A completion during the call has an exit code; a continuing process has a process session identifier. Preserve field absence instead of fabricating values. Nonzero exits are ordinary command results where the baseline uses that form. Keep partial output and the distinction between launch errors, command exits, tool failures, and script exceptions.

11. **Two kinds of continuation.** Execution cells use unique string identifiers consumed by `wait`; running commands use numeric session identifiers consumed by `write_stdin`. Do not conflate their state or identifiers. Initial execution waits for completion, explicit yielding, or its yield deadline; the deadline returns a running result without cancellation. Waiting returns only output since the last collection and closes a completed cell once. Collection uses a precise sequence cutoff so later output belongs to the next result. Serialize collection for the same cell; different cells remain independent. Waits use worker events, a completion promise, and one deadline timer per active collector, with no periodic polling. Ordinary text does not wake a pending wait; explicit yield, completion, termination, and its deadline do. Concurrent-wait arbitration and caller-only cancellation are accepted package rules until independently observed in the reference. Preserve the declared 10,000 ms wait and 10,000-token defaults. Command polling preserves its own incremental behavior. Do not substitute native line or byte limits for captured token budgets.

12. **Shell preferences and context.** Resolve defaults from the owning execution context, not the extension process's startup directory. Use an explicitly supplied command shell when present, the effective Pi shell preference as its configured default, and the captured default-shell behavior otherwise. Apply Pi's effective command prefix once per launched command. Preserve inherited environment, Pi's managed executable search path, and fresh session metadata. Clear stale inherited session metadata as native execution does. Read effective settings through Pi's public service so trusted project settings and in-memory overrides remain in effect.

13. **Process ownership and output.** Support pipes and PTYs, retained process handles, input delivery, output polling, completion, and cancellation. A yield deadline is not a process timeout. Reuse suitable public or installed facilities, but do not force the native completion-only shell operation interface to act as a PTY or process-session API. Processes and cells share asynchronous output storage. Retain small output in memory and spill larger unread output through batched writes to private temporary files. Apply producer backpressure, including worker-to-host credits outside script globals and paused process streams, before queues grow without bound. Preserve ordered text and images, valid decoding, trailing output, byte/line counters, and collection cutoffs. Read only the new ranges needed for the requested output budget, without repeatedly concatenating or rescanning delivered data. Cell completion alone must not kill a command that already returned its own process handle.

14. **Native dispatch and results.** Run nested operations through `ctx.executeTool()`, not a tool factory's raw `execute()` method. Pass the cell's signal explicitly and recheck the current callable surface and existing core-availability rules on every invocation. Preserve validation, blocking hooks, argument mutation, result mutation, and normal image processing. Return the processed outcome and associate it with the invocation's promise and a package child identifier made from its cell ID and a monotonically increasing counter. Never reconstruct content discarded by a hook in returned results or subsequent model context, including removed structured content. Live command presentation has the explicit timing distinction in decision 28. Pi still supplies native event IDs and its current runtime context; hooks depending on original background-cell identity may behave differently after a yield. Package IDs do not repair those native IDs, native nested history, usage attribution, or late update delivery. Follow Pi's actual registration precedence and callable-tool rules; a hidden declaration is not a permission boundary.

15. **Permissions and integrations.** Pi supplies operating-system permissions and any configured extension or external restrictions; project trust controls resource loading. This package adds no separate approval or sandbox system. Retain the captured permission-related command argument shapes, whose default selection is `use_default`, while honoring Pi's actual authority. Do not invent an approval, elevated access, or isolation guarantee that Pi does not provide. A request requiring an unavailable authority must fail clearly. Hooks keyed to old tool names and injected remote or sandbox operation objects are not automatically transferable. The currently inspected packages do not require such translation; a general translator or remote-backend abstraction is outside this release.

16. **Patches and file integrity.** Implement the selected patch behavior for creating, updating, moving, and deleting files. Verify syntax, matching, validation order, partial-failure behavior, returned changes, and errors against the frozen baseline. Preserve unrelated content and applicable encoding, BOM, and newline behavior. Reuse public `withFileMutationQueue` for local mutations so operations coordinate with native edits and writes, including existing symlink aliases. Do not add another lock service or promise cross-process locking, atomic multi-file transactions, rollback, or cancellation undo. Native fuzzy replacement, argument repair, and path convenience rewriting are not part of the replacement contract merely because native tools provide them.

17. **Images and settings.** Check effective `images.blockImages` before `view_image` reads or returns image bytes or a data URL. A blocked outcome contains no image bytes, including when emitted through `text`. Otherwise, emit images through Pi's normal result pipeline. Preserve `images.autoResize` and the effective routed model's limits, without duplicating normalization against possibly different selected-model metadata. Pi may resize or convert an image despite an original-detail request; this is an accepted host-processing difference. Terminal image visibility remains independent. This rule governs the image operation and normal image emission, not generic scanning of arbitrary shell or text output for encoded data.

18. **Lifecycle and cancellation.** Live commands, execution cells, timers, and temporary stored values belong to the active extension session. Cells retain the originating tool-call ID and session identity, but their cancellation controllers are separate from the original prompt. Cancelling the initial `exec` before it yields stops that newly started cell. Reaching a yield deadline or completing an ordinary prompt preserves it. Cancelling a later `wait` stops that caller's wait and preserves the cell and uncollected output. `wait({ terminate: true })` stops the cell and cancels its pending operations. This follows the approved package contract and differs from the current reference observation, where an awaited command survived explicit cell termination. Stop accepting operations before aborting calls and terminating the worker. Preserve available output and bound cleanup time; report incomplete cleanup accurately. Normal shutdown, reload, quitting, and session replacement through new, resume, or fork stop all owned live work and clear temporary state. File changes and retained history remain. There is no daemon, process-global survival registry, or restoration of live handles from history. Failed or stale handles produce clear results rather than binding to unrelated new work.

19. **Continuing activity records.** Public nested dispatch ends its retained scope with the original parent. The approved continuation contract therefore makes the package responsible for compact cell activity records through `pi.appendEntry()`, which excludes them from model context. Keep stable originating call, cell, child-operation, and process identities, effective operation context, processed outcomes, and terminal status. Retain bounded incremental presentation data needed to recover operation details and available readable output; bounded argument summaries alone do not contain successful child results. Preserve original tool calls, orchestration source, and transport results unchanged. Do not repeat full command output, image bytes, or a growing snapshot in each entry. Flush incremental batches when full and at yields, collection, cell and process settlement, and termination, including late activity after the parent returns. Keep routine entries invisible through the public entry-rendering interface and present their information within the originating tool card. Normal `exec` and `wait` results remain the model's output. Reconcile retained records as specified in decision 27; they never recreate live resources. Preserve blocking and result hooks through public dispatch, while documenting native hook ID/context and notification differences. Do not copy the dispatcher, modify Pi, or introduce a private lifetime adapter.

20. **Native composition.** Preserve the configured composer, attachments, skill references, chat presentation, web tools, and prompt/lifecycle extensions. Pi continues to own provider composition, conversation data, retained history, native tool events, and terminal behavior. Tool renderers retain ownership of expanded tool presentation. Generic action labels for newly registered tools are acceptable; this package does not add a chat-specific protocol or infer file operations by parsing arbitrary shell strings. User-entered shell commands remain on their native path.

21. **Internal boundaries.** Keep contract registration and loadout handling, execution-cell state, command-process state, patch execution, local image conversion, and parent tool presentation as the necessary responsibilities. Extend the existing execution and process modules with the identities, events, and retained presentation data their tool renderers need. Prefer existing public helpers and mature installed dependencies. Add only the boundaries needed to implement and verify those responsibilities; do not introduce a general adapter framework, alternate provider stack, configuration surface, or separate history store.

22. **Artifact naming and documentation.** The exact package identifier `pi-codex-tools` is the sole approved source-application naming exception. Names identifying the source application, its vendor, or related products must not appear elsewhere in implementation artifacts, instructions, fixtures, comments, diagnostics, or documentation. Keep only the required glossary, justified architecture decisions, this specification, and individual tickets as documentation. Existing resolved terminology and architecture decisions already cover the core toolset, public extension contracts, and lifecycle; no additional glossary or architecture document is needed for routine implementation details.

23. **Resource and performance limits.** Use finite internal limits for live workers, retained cells, pending operations, message and queue bytes, unread output, journal batches, serialized values, and presentation buffers. Record the chosen limits and overflow outcomes in the affected tickets. Exceeding an execution limit returns an explicit failure and never silently discards a live handle; presentation limits show that content was omitted without changing model collection. A worker message queue must be bounded before posting; a bounded result buffer alone is insufficient. Measure short completed calls against commit `6bac1a2`, then repeated waits, output-heavy and concurrent cells, worker startup, and cleanup without model latency. Record median and tail latency, peak memory, and main-thread delay. Acceptance requires no worker creation on wait, no periodic polling, collection proportional to newly collected output, bounded queues, incremental history writes, and an explained short-call regression if any. For the presentation revision, compare with the completed core implementation, reuse native redraw batching, and avoid copying or persisting the entire accumulated output on every event. Release presentation subscriptions and invalidation callbacks when their owning session ends; completed records need no worker, process, or polling timer. Add no tuning options or pool of reused JavaScript isolates.

24. **Native parent renderers.** Register custom `renderCall` and `renderResult` for both `exec` and `wait`. Default presentation is a compact action summary and status. Expansion shows nested operations and readable results inside their parent card, including command, effective working directory, output, and exit status for commands; readable file-change results for patches; and image paths and status. Actual images use native presentation in the result that collects them, as described in decision 25. Present script-emitted text and script failures readably in the originating card as well. Neither collapsed nor expanded cards show orchestration JavaScript, internal identifiers, transport headers, escaped result envelopes, or encoded image data as their ordinary presentation. Preserve those original inputs and results in retained history. Keep tool and script errors visible, including a failure before any child starts. Supply tool-owned presentation data through `details` and complete `onUpdate` snapshots while a call is pending; use public renderer invalidation for later changes to an existing card. Native result renderers do not automatically receive structured content or retained nested-call records, and child renderers alone do not create nested operation presentation. Reuse native components, themes, and expansion controls.

25. **Originating-card ownership.** Associate each underlying operation with the `exec` call that started it using stable package identity, independent of Pi's current prompt context or nested-call IDs. Keep its status and accumulated text there across yields, cell collection, and later prompts. A process session retains its original command ownership even when another cell invokes `write_stdin`; represent that input or collection action in its caller without copying or moving the command's output. A `wait` card reports its own waiting, collection, termination, cancellation, or error outcome without replaying operation text. Images are the approved native-display exception: an emitted image appears once in the result that collects it, including `wait` after a yield; its operation path and status remain in the originating card. Preserve native image processing, result hooks, terminal preferences, and model content. Do not duplicate image payloads into the origin, mutate native components, or move images through a provider bypass. Waiting still returns newly collected output to the model under the unchanged contract. Neither normal text collection nor a new prompt transfers display ownership. Keep cell completion and command completion distinguishable; a returned process handle indicates a continuing command, not a successful exit.

26. **Live process presentation.** Observe the existing pipe and PTY output events and process lifecycle events in the package's execution path. Show output while `exec_command` or `write_stdin` is still pending, and continue updating the original card after a yield or after its cell has settled while a command remains alive. Record effective command arguments and working directory from execution after normal argument processing. Preserve output ordering and accumulated progress, including final trailing output, launch errors, cancellation, and late exits. Display observation must not advance collection cursors, drain buffers needed by the model, alter token budgets or return boundaries, or turn command exit codes into script exceptions. Use Pi's screen-refresh batching; add no display-driven polling, hidden collection calls, extra tool dispatch, refresh loop, or provider-context entries.

27. **Recorded status and recovery.** Resolve a card from its live state and ordered records on the active branch, scoped to the originating session and call. A later terminal record supersedes an earlier running record for the same cell or operation. Cell collection or registry removal must not downgrade a recorded completion to interrupted or unknown. Process lifecycle can continue beyond cell settlement; its later outcome remains attached to its original operation. After reload, resume, or branch changes, restore the latest recorded status and retained readable details without restarting workers, restoring process handles, rerunning commands, or assigning old activity to a new request. Use interrupted or unknown only when no live state or recorded terminal outcome establishes the result. Older records that lack output or effective context remain usable with their available original data; disclose unavailable details instead of fabricating them. Late failures remain visible and recorded even if the agent never collects again. Presentation does not consume failures or output available through `wait` or `write_stdin` under the existing continuation rules.

28. **Hooks and notifications.** Returned child and parent results retain Pi's normal result hooks, and provider encoding continues to respect later context edits. Presentation data and retained records must never restore removed content to a returned result or model request. Live command output can appear before the returned-result hooks run; later redaction cannot prevent text already being seen. This visibility is an accepted property of the approved live presentation, not a promise of prior redaction. Treat post-hook results as authoritative when rendering returned results rather than recovering a discarded payload from another source. Do not add automatic notifications or model turns for command, cell, or late background failures. Leave ordinary turn notifications to Pi and preserve the existing explicitly invoked `notify()` helper.

29. **Terminal rendering and composition.** Use Pi's public terminal-width and ANSI-aware utilities for clipping and wrapping every presentation path. Respect display cells, wide characters, combining text, and emoji; never clip by UTF-16 length or split an escape sequence, including across output events. Respect terminal image visibility, native expansion state, and manual or global expansion controls. Keep bounded previews and indicate omitted content. Operation limits retain active work and a bounded window of the most recently settled operations; omitted failures still affect aggregate status. Apply the same retention policy during history recovery. Routine activity records add no visible journal rows or artificial activity-group boundaries. Generic extension action labels and Pi's native tool shell remain valid; do not parse orchestration or shell text to change the chat package's labels, grouping, or work composition.

## Out of Scope

- Collaboration, subagents, goals, scheduling, asynchronous user-question tools, clocks, web or browser tools, external tool discovery, desktop automation, worktree management, and application UI integration.
- Additional direct read, edit, write, search, list, or alternate-shell aliases.
- Audio, generated-image helpers, public protocol image-content overloads, and their unused metadata or shared types.
- Replacing Pi's full instructions, workspace guidance, skills, provider stack, model settings, repository-context assembly, compaction, or conversation management.
- A separate approval engine, generic permission-policy translation, automatic inheritance of injected remote/sandbox operations, or a compatibility framework for integrations not used by the current setup.
- Modifying Pi source, using private runtime integration, requiring the source application or its binaries at runtime, or maintaining live work outside Pi's normal extension lifecycle.
- Automatic baseline updates, multiple contract profiles, platform/provider/version guard frameworks, broad portability work, or speculative configuration.
- Changes to `pi-chat`, including work-folding, custom-entry identity, action labels, or grouping repairs. Native tool renderers in this package own the presentation correction.
- A separate presentation framework, replacement terminal controls or tool shell, orchestration/debug panes in expanded cards, custom action-label inference, or full output duplicated in every history entry.
- Display-driven polling, extra tool calls to obtain UI progress, automatic late-failure alerts, or unsolicited model turns. The existing explicit notification helper remains in scope.
- Retroactively recovering output that older history did not retain, recreating live resources from history, or guaranteeing that result hooks prevent prior live visibility.
- Transaction/rollback services or stronger filesystem guarantees than the agreed behavior supplies.
- Identical entire requests across different applications, identical generated prose, claims about undocumented training data, or unmeasured performance improvements.
- Extra comparison reports, general design documents, or other documentation beyond the four requested workflows.
