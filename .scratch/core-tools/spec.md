## Problem Statement

A patch can currently report success while losing an earlier edit. Whole-patch validation caches complete replacement contents; a later operation through a symlink alias or a move's destination can write that old snapshot over the earlier operation's result. The same cached contents can make per-file diffs and counts inaccurate.

Pi's built-in tools give the agent a different interface for commands, file changes, and images from the fixed tool contract the user wants to use. Tool names alone do not account for the difference. Declarations, instructions, argument encoding, execution, continuation, errors, output limits, and the results sent back to the model all affect how the agent works.

The user needs a package that provides the selected contract while retaining the configured Pi experience. Replacing tools must preserve effective host settings, native interception, explicit tool selection, retained history, and independently installed extensions. A renamed wrapper around the existing tools would neither reproduce the intended behavior nor automatically preserve every integration.

The user also needs verifiable comparisons. Similar answers or a successful demonstration do not establish that the model received equivalent tools or that tool execution behaved the same way.

The toolset must describe actual operations separately from the calls that collect their results. Package-specific chat decoding couples independent extensions and turns collection or empty execution receipts into visible actions. The neutral activity contract supplies semantic facts usable by any consumer while preserving execution and model-facing results.

## Solution

Keep whole-patch validation and the existing public file mutation queues. At application time, reread each update's source and recompute its replacement before writing, so operations compose in order. Capture before/after facts from the contents each operation actually encounters. A later read or match failure preserves earlier changes and reports the current operation as failed and later operations as unattempted.

Create the self-contained Pi extension package `pi-codex-tools`. It supplies the core toolset through two direct model tools, `functions.exec` and `functions.wait`. JavaScript executed by `functions.exec` can call four selected tools: `exec_command`, `write_stdin`, `apply_patch`, and `view_image`.

Commands cover local execution, text reading, searching, and listing. Patches cover file creation and modification, including moves and deletion. The image tool and image output helper cover local image inspection. The package replaces equivalent stock built-in capabilities without taking over unrelated extension tools or the rest of the agent interface.

The captured contract is the baseline for the included tool names, declarations, instructions, arguments, results, and behavior. Pi's effective settings, public dispatch, result processing, and normal extension lifecycle remain authoritative. The package owns continuing cells and records their activity through public custom entries. Native nested-call identifiers, native attribution after a yield, and notification transport and timing are accepted host differences; they are not repaired by package-owned identifiers.

Verification uses the existing real Pi host with controlled provider responses. It observes the outgoing model request, executes the requested tools against real temporary resources, and examines the next outgoing request. Matched live-model trials then measure behavior under equivalent task conditions.

This revision publishes the optional neutral activity contract. It preserves stable operation identity, effective inputs, individual outcomes, bounded applicable output, per-file changes, and separately owned script output or errors. A command can have several meaningful submitted actions. Successful polls and empty orchestration completions produce no action. No consumer name, renderer, summary, or layout belongs in this package.

Command output and process outcomes update their origin through existing process events, independently of model collection or custom renderer creation. Pi result details, event bus, and retained custom entries carry the same validated contract. Original source, result hooks, native image placement, and standalone tool rendering remain intact. Add no polling, extra calls, alerts, settings, or unsolicited turns. The [generic activity specification](../../docs/specs/pi-activity.md) governs the delta.

## Implementation Decisions

1. **Scope and target.** Deliver one package for the measured macOS arm64 environment and the configured Responses-compatible provider path. Use normal package discovery, public extension registration, public provider composition, and public lifecycle events. Do not modify Pi, install private runtime adapters, or add platform, provider, or version guard frameworks. Preserve the existing boundary that private integration is an exception for the chat package alone.

2. **Frozen baseline.** Use captured baseline `local-tools-reference-20261013`, identified by canonical source SHA-256 `c96638241baa0167c3603823374d67a616a4d4df5142496a1d13971ece498843`. The canonical encoding is sorted-key, compact UTF-8 JSON. This checksum identifies the complete source capture, not an implemented or validated scoped contract. Extract only the included tool declarations and behavior cases; give that scoped fixture its own identity when created. Updates are deliberate package changes, with no runtime synchronization, alternative profiles, or installed-application dependency.

3. **Two direct tools.** The outgoing selected tool surface exposes `functions.exec` and `functions.wait` with the captured namespace, input form, descriptions, schemas, required fields, optionality, and constraints. `exec` accepts raw JavaScript with the optional first-line execution pragma; it must not become a model-facing JSON code wrapper. `wait` accepts its captured object schema. Preserve the included instructions without broad paraphrasing. Remove only the approved out-of-scope tools, helper overloads, metadata, and related explanatory text.

4. **Four nested tools.** The execution environment exposes `exec_command`, `write_stdin`, `apply_patch`, and `view_image` through its `tools` object. Text reading, searching, and listing use commands. There are no additional read, write, edit, search, list, or alternate-shell aliases. Register the selected operations with Pi so nested calls retain native dispatch. Use public exposure and loadout controls to separate model declarations from callable operations; never confuse a hidden declaration with a permission restriction.

5. **Selection and ownership.** Replace the equivalent stock `bash`, `read`, `edit`, `write`, `grep`, `find`, and `ls` surface only within the user's enabled scope. Explicit Pi selection and exclusions remain authoritative. Do not reactivate excluded registrations to satisfy a hardcoded list. Preserve unrelated tools, their order and model-dependent availability, and extension-owned overrides identified through public provenance. Retained historical calls are not renamed or rewritten. Newly loaded tools apply on the next request after normal loading or reload, including in an existing conversation.

6. **Execution runtime.** Each `exec` evaluates an async JavaScript module in one fresh worker and V8 context with the selected host helpers. It exposes no direct Node, filesystem, network, or console APIs. The selected command and file tools remain the route to host operations; this runtime isolation is not advertised as an operating-system sandbox. Preserve the captured restriction against running an outer `exec` invocation in parallel with other tool invocations; independent nested calls may run concurrently when Pi permits them. The session-owned execution module exposes `start`, `wait`, and `close`. Each cell keeps its worker across yields; waits never create a worker, restart a script, or replay work. Cells transition from running to completed, failed, or terminated, then to collected. Release a settled worker promptly, retaining unread output, the terminal result, and any metadata still needed for pending host-operation cleanup. Script completion discards unawaited JavaScript promises and timers; it does not imply cancellation of already dispatched host operations or independent process sessions.

7. **Retained helpers.** Keep `text`, `image`, `exit`, `store`, `load`, `notify`, `setTimeout`, `clearTimeout`, and `yield_control`. Keep `ALL_TOOLS` as name/description metadata restricted to the selected tools available when the cell starts; recheck current availability at each dispatch. `text` appends output and stringifies non-string values when possible. `notify` uses a public custom message with `triggerTurn: false`, without duplicating its content into ordinary output or starting a turn. This differs from an extra tool-output event: while Pi is streaming, delivery is deferred until its safe turn boundary. `exit` successfully ends the script. Worker-owned timers do not keep an otherwise completed script alive; timer exceptions fail the cell and termination clears callbacks. `yield_control` returns accumulated output while the same execution continues.

   Store serialized values in a bounded session map. Each cell receives one snapshot and tracks only keys it writes; each `load` parses a copy, and a missing key returns `undefined`. Pending writes remain invisible to overlapping cells. Merge changed keys on normal completion, `exit`, and an ordinary script or timer exception. Discard pending writes on termination or cancellation of the initial execution. Session replacement and reload clear all values. A cell must not overwrite unrelated writes committed by another cell. Copy a bounded snapshot at startup; do not add a cross-thread lookup service without measured need.

8. **Image helper scope.** Retain data-URL input and the ordinary object form carrying `image_url` and optional `detail`, including the captured ordinary detail variants and explicit-detail override. Exclude public protocol image-content objects, their metadata, audio emission, generated-image emission, and the shared types or forwarding examples needed only by those excluded helpers. Network image URLs are not introduced.

10. **Command results.** Preserve the command APIs' required `output` and `wall_time_seconds` fields and optional `chunk_id`, `exit_code`, `original_token_count`, and `session_id` fields. A completion during the call has an exit code; a continuing process has a process session identifier. Preserve field absence instead of fabricating values. Nonzero exits are ordinary command results where the baseline uses that form. Keep partial output and the distinction between launch errors, command exits, tool failures, and script exceptions.

11. **Two kinds of continuation.** Execution cells use unique string identifiers consumed by `wait`; running commands use numeric session identifiers consumed by `write_stdin`. Do not conflate their state or identifiers. Initial execution waits for completion, explicit yielding, or its yield deadline; the deadline returns a running result without cancellation. Waiting returns only output since the last collection and closes a completed cell once. Collection uses a precise sequence cutoff so later output belongs to the next result. Serialize collection for the same cell; different cells remain independent. Waits use worker events, a completion promise, and one deadline timer per active collector, with no periodic polling. Ordinary text does not wake a pending wait; explicit yield, completion, termination, and its deadline do. Concurrent-wait arbitration and caller-only cancellation are accepted package rules until independently observed in the reference. Preserve the declared 10,000 ms wait and 10,000-token defaults. Command polling preserves its own incremental behavior. Do not substitute native line or byte limits for captured token budgets.

12. **Shell preferences and context.** Resolve defaults from the owning execution context, not the extension process's startup directory. Use an explicitly supplied command shell when present, the effective Pi shell preference as its configured default, and the captured default-shell behavior otherwise. Apply Pi's effective command prefix once per launched command. Preserve inherited environment, Pi's managed executable search path, and fresh session metadata. Clear stale inherited session metadata as native execution does. Read effective settings through Pi's public service so trusted project settings and in-memory overrides remain in effect.

13. **Process ownership and output.** Support pipes and PTYs, retained process handles, input delivery, output polling, completion, and cancellation. A yield deadline is not a process timeout. Reuse suitable public or installed facilities, but do not force the native completion-only shell operation interface to act as a PTY or process-session API. Processes and cells share asynchronous output storage. Retain small output in memory and spill larger unread output through batched writes to private temporary files. Apply producer backpressure, including worker-to-host credits outside script globals and paused process streams, before queues grow without bound. Preserve ordered text and images, valid decoding, trailing output, byte/line counters, and collection cutoffs. Read only the new ranges needed for the requested output budget, without repeatedly concatenating or rescanning delivered data. Cell completion alone must not kill a command that already returned its own process handle.

14. **Native dispatch and results.** Run nested operations through `ctx.executeTool()`, not a tool factory's raw `execute()` method. Pass the cell's signal explicitly and recheck the current callable surface and existing core-availability rules on every invocation. Preserve validation, blocking hooks, argument mutation, result mutation, and normal image processing. Return the processed outcome and associate it with the invocation's promise and a package child identifier made from its cell ID and a monotonically increasing counter. Never reconstruct content discarded by a hook in returned results or subsequent model context, including removed structured content. Live command presentation has the explicit timing distinction in decision 28. Pi still supplies native event IDs and its current runtime context; hooks depending on original background-cell identity may behave differently after a yield. Package IDs do not repair those native IDs, native nested history, usage attribution, or late update delivery. Follow Pi's actual registration precedence and callable-tool rules; a hidden declaration is not a permission boundary.

15. **Permissions and integrations.** Pi supplies operating-system permissions and any configured extension or external restrictions; project trust controls resource loading. This package adds no separate approval or sandbox system. Retain the captured permission-related command argument shapes, whose default selection is `use_default`, while honoring Pi's actual authority. Do not invent an approval, elevated access, or isolation guarantee that Pi does not provide. A request requiring an unavailable authority must fail clearly. Hooks keyed to old tool names and injected remote or sandbox operation objects are not automatically transferable. The currently inspected packages do not require such translation; a general translator or remote-backend abstraction is outside this release.

16. **Patches and file integrity.** Implement the selected patch behavior for creating, updating, moving, and deleting files. Verify syntax, matching, validation order, partial-failure behavior, returned changes, and errors against the frozen baseline. Preserve unrelated content and applicable encoding, BOM, and newline behavior. Reuse public `withFileMutationQueue` for local mutations so operations coordinate with native edits and writes, including existing symlink aliases. Validate every operation against the initial state before writing, then reread and recompute each update against its application-time source contents. Do not use preflight replacement contents for writes. Retain the existing repeated-source-path validation; do not reject otherwise valid alias or move-destination overlaps to avoid handling their order. A read or match failure during application is a partial runtime failure: retain completed effects, fail the current record before it writes, and leave later records unattempted. Preserve cancellation checks around reads and mutations. Do not add another lock service or promise cross-process locking, atomic multi-file transactions, rollback, or cancellation undo. Native fuzzy replacement, argument repair, and path convenience rewriting are not part of the replacement contract merely because native tools provide them.

17. **Images and settings.** Check effective `images.blockImages` before `view_image` reads or returns image bytes or a data URL. A blocked outcome contains no image bytes, including when emitted through `text`. Otherwise, emit images through Pi's normal result pipeline. Preserve `images.autoResize` and the effective routed model's limits, without duplicating normalization against possibly different selected-model metadata. Pi may resize or convert an image despite an original-detail request; this is an accepted host-processing difference. Terminal image visibility remains independent. This rule governs the image operation and normal image emission, not generic scanning of arbitrary shell or text output for encoded data.

18. **Lifecycle and cancellation.** Live commands, execution cells, timers, and temporary stored values belong to the active extension session. Cells retain the originating tool-call ID and session identity, but their cancellation controllers are separate from the original prompt. Cancelling the initial `exec` before it yields stops that newly started cell. Reaching a yield deadline or completing an ordinary prompt preserves it. Cancelling a later `wait` stops that caller's wait and preserves the cell and uncollected output. `wait({ terminate: true })` stops the cell and cancels its pending operations. This follows the approved package contract and differs from the current reference observation, where an awaited command survived explicit cell termination. Stop accepting operations before aborting calls and terminating the worker. Preserve available output and bound cleanup time; report incomplete cleanup accurately. Normal shutdown, reload, quitting, and session replacement through new, resume, or fork stop all owned live work and clear temporary state. File changes and retained history remain. There is no daemon, process-global survival registry, or restoration of live handles from history. Failed or stale handles produce clear results rather than binding to unrelated new work.

## Provider activity contract

The [neutral activity specification](../../docs/specs/pi-activity.md) defines the public consumer boundary. Semantic operations identify their originating call/session, stable order and revision, kind, actual outcome, applicable inputs/output, optional verified counts, and explicit omission. Native result details bind those facts to processed content; live events and retained custom-entry metadata publish incremental updates independently of custom renderers. Image ownership references native result parts without copying bytes.

A valid empty record means the call has no new activity; missing or invalid metadata means generic fallback. Private execution details and journals may continue serving standalone rendering and model replay, but consumers do not decode them. Result consistency checks cover text/content shape and activity facts, with the existing exception for native image conversion and normalization hints. They are not authentication. Removed or invalid metadata never revives discarded output from an earlier journal. Session replacement clears live state; replay uses only reliable active-branch records and never recreates resources.

Settled execution bodies retain the latest eight operations; patch bodies retain the latest sixteen changes. These windows remove body content, never compact operation or file records. The existing presentation helper uses a 16,384-column and byte budget with an omission marker for truncated text. Patch count calculation trims unchanged prefixes and suffixes, then bounds mixed comparison to 100,000 cells and 10,000 combined lines; pure additions and deletions remain exact. Unreadable prior content or a larger mixed comparison omits counts. These limits do not change returned command output collection or file mutation semantics.

Output attribution follows object identity before serialization: forwarding a returned child object through `text` or `image` preserves its producing operation. Primitive text has no such identity. A tool or result hook can return a string, and a script can catch a primitive rejection; emitting either through `text` cannot be distinguished from emitting identical script-owned text. That output is retained as execution content and can therefore appear in both bodies. Equality alone never removes it. Native primitive rejection values and helper return semantics remain unchanged; complete attribution for primitive forwarding is not established.
