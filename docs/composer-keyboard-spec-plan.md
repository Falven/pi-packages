# Ghostty keybinding setup and page selection

Ghostty setup and page selection are implemented through the [composer specification](specs/pi-composer.md). Public-host acceptance is recorded in the [verification record](../.scratch/composer-keybinds/verification.md); physical acceptance remains open in [ticket 03](../.scratch/composer-keybinds/issues/03-verify-keybindings-in-ghostty.md). [ADR 0010](adr/0010-explicit-terminal-keybinding-setup.md) defines the explicit, removable configuration block.

## Implementation and acceptance

| Work                            | Result                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Page selection                  | Effective native page bindings extend the shared source selection by the visible composer height. Tests cover both views, anchors and reversal, wrapping, Unicode, resizing, history, and native ownership.                                                                                                                                      |
| Ghostty setup                   | Public commands review, install, repeat, and remove the eight-rule block in a supported configuration. Verification supports Ghostty 1.3.1 with one owned, regular Application Support configuration, no XDG files or includes, no extra launch arguments, and a verified matching Ghostty ancestor. Unverified configurations remain unchanged. |

The computer-use tool denied Ghostty access.                                                                                                                                                      |

The companion paste, attachment, and skill-reference specifications retain their behavior and package ownership. Combined acceptance uses their existing native interfaces. The original native editing results remain in the [keyboard verification record](../.scratch/composer-keyboard/verification.md).

## Verification evidence

The installed target is Ghostty 1.3.1, build 15212, on macOS 27.0.1. Behavior tests use the workspace's locked Pi 1.0.2 on Node 24.13.1. A separate source-loading check through local Pi 1.1.0 loaded all four packages and registered `setup-keybinds` without errors; that check did not run the command interactively.

Ghostty's candidate validator and current-binding inspectors do not provide an arbitrary prospective effective-configuration query. The demonstrated [single-source proof](../.scratch/composer-keybinds/issues/02-set-up-and-remove-ghostty-keybindings.md#verification) combines native validation and freshly loaded baseline inspection with verified loading order and Ghostty's last-binding-wins semantics. The optional Darwin process-context probe is an unstable platform prerequisite and fails closed when unavailable. Native validation and temporary-file tests establish their own boundaries; physical forwarding and the GUI's reloaded state still require the [terminal procedure](terminal-checks.md).

The unchanged-configuration baseline remains the user's report: Cmd+A, Cmd+Enter, Cmd+Up/Down, Cmd+Z/Shift+Z, and Shift+Fn+Up/Down fail; Cmd+Shift+Up/Down works, and Cmd+C appears to work. These reports are distinct from observed delivered-input results. The acceptance work changed no live terminal settings and did not perform physical gestures.
