# Composer keyboard spec revision plan

This plan defines the next revision of the composition specifications. The required outcome is reliable editing through Pi's effective actions, with terminal delivery documented and verified separately. Source and formatted views retain one Markdown draft, selection, and undo history.

The governing decisions are [native Pi contracts](adr/0001-preserve-pi-extension-contracts.md), [draft ownership](adr/0002-one-editor-owns-draft-transactions.md), [native editing actions](adr/0009-pi-composer-native-editing-actions.md), and [terminal ownership](adr/0010-scope-terminal-integration-to-pi.md).

## Editing behavior to specify

A **line** is a logical line separated by a newline. A **visual row** is a displayed row after wrapping. Line commands target logical boundaries; vertical movement follows visual rows. In formatted view, visible positions map to the shared Markdown source without exposing hidden delimiters as stray caret stops.

In the tables below, Delete refers to the Mac backward-delete key, named `backspace` in Pi's bindings. Forward delete is a separate action. Default keys illustrate native behavior; the supplied manager determines the effective binding after user configuration.

| Operation                                          | Pi action or existing composer behavior                                                      | Required result                                                                                                                                                                        |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Backward/forward character deletion                | `tui.editor.deleteCharBackward`, `tui.editor.deleteCharForward`                              | Remove the selection or one whole grapheme in the requested direction.                                                                                                                 |
| Backward word deletion                             | `tui.editor.deleteWordBackward`; default Ctrl+W / Alt+Backspace                              | Execute against the composer draft. Option+Delete works when the terminal delivers this native input.                                                                                  |
| Forward word deletion                              | `tui.editor.deleteWordForward`; default Alt+D / Alt+Delete                                   | Preserve native word-deletion behavior, including line joining at a logical boundary.                                                                                                  |
| Delete toward either line boundary                 | `tui.editor.deleteToLineStart`, `tui.editor.deleteToLineEnd`; default Ctrl+U / Ctrl+K        | Delete the requested range. At the corresponding line boundary, retain native newline deletion and line joining. Ghostty's Cmd+Delete translation to Ctrl+U uses this same action.     |
| Recover native word/line deletions                 | `tui.editor.yank`, `tui.editor.yankPop`                                                      | Retain deleted contents using native accumulation semantics; yank inserts retained text and yank-pop replaces the preceding yank. These edits participate in the same undo history.    |
| Line-start/end movement                            | `tui.editor.cursorLineStart`, `tui.editor.cursorLineEnd`; default Home/Ctrl+A and End/Ctrl+E | Use logical line boundaries in either view. Ghostty's Cmd+Left/Right translations retain their meaning.                                                                                |
| Cmd+Up/Down                                        | Composer aliases for line-start/end movement                                                 | Move to the start/end of the current logical line. Shift variants extend the existing selection.                                                                                       |
| Up from the first visual row of an ordinary draft  | `tui.editor.cursorUp`                                                                        | Reach the first line's beginning before another unmodified Up can enter native prompt history. Preserve native empty-editor and active-history behavior.                               |
| Down from the last visual row of an ordinary draft | `tui.editor.cursorDown`                                                                      | Reach the last line's end. Preserve native next-history behavior while browsing prompt history.                                                                                        |
| Shift-modified movement                            | Effective native movement bindings and supported composer aliases                            | Keep the original anchor, extend the moving end, and remain in the draft at its boundaries.                                                                                            |
| Word movement                                      | `tui.editor.cursorWordLeft`, `tui.editor.cursorWordRight`                                    | Continue using Pi's decoding and configured actions, including Ghostty's legacy Option+Arrow sequences.                                                                                |
| Option+Up/Down                                     | Pi application dispatch                                                                      | Retain Pi's effective behavior, including the default dequeue action on Option+Up.                                                                                                     |
| Select all, redraw, then edit                      | Composer select-all action                                                                   | Keep the full draft selected through redraw, resize, view changes, and preview updates until another editing or selection action changes it. Typing replaces it; one undo restores it. |
| Copy, cut, paste, undo, redo, and submission       | Existing draft and host routes                                                               | Preserve clipboard failure recovery, coherent undo, contextual Enter, explicit submission, and native steer/follow-up behavior. Picker handling keeps its native priority.             |

All deletion operations consume a nonempty selection before computing an unselected word or line range. Formatted deletion must preserve surrounding Markdown and code, and undo must recover the text, selection, and attachment membership together. Native retained-text recovery must use the same draft rather than the inherited editor's private text and history.

The spec revision must define retained Markdown for a whole formatted span, a partial span, and a selection crossing spans, including consecutive deletions and insertion into another formatting context. Projection can remove enclosing delimiters outside the immediate caret range, so retaining a simple source slice does not by itself establish complete recovery. Add concrete before/delete/yank/undo examples for these cases before implementing retained-text recovery.

Audit the remaining native editor actions when revising the action contract: character jumps, prompt history, and editor paging must have an explicit owner and observable behavior. Fullscreen PageUp/Down are normally handled by Pi's viewport before editor dispatch; configured editor paging must preserve that distinction. Existing native actions cannot be silently swallowed by the replacement editor or bypass host-owned UI.

## Binding and dispatch contract

The effective input path is terminal shortcut handling, Pi decoding and native dispatch, then a composer operation if the editor receives the input. A key consumed by the terminal cannot be recovered by raw mode, keyboard protocol negotiation, or a shell key mapping. Useful terminal translations continue through the native action manager.

The specification must preserve these dispatch rules:

1. Existing terminal-input listeners, fullscreen viewport handling, overlays, and focused components retain host ownership of their input.
2. Extension shortcuts accepted by Pi retain its dispatch and conflict rules. Native clipboard, interrupt, exit, explicit prompt history, and other application actions retain their context-sensitive precedence.
3. Preserve Pi's action-specific autocomplete precedence: native undo runs before picker key handling; picker navigation, acceptance, and cancellation retain their native handling before ordinary editor fallbacks.
4. Effective native editing actions resolve before fixed composer aliases. For example, a native deletion action configured on Cmd+A performs that deletion instead of selecting all.
5. Composer aliases for a native action apply only while that action has no explicit Pi binding override. Changing or clearing its bindings suppresses those aliases, including Shift variants. Remaining supported aliases act on the shared draft, and a physical keystroke produces at most one operation.

Resolve actions through the manager passed to the editor factory. Do not parse the user's keybinding file again, add a parallel manager, mutate the host's configured bindings, or reach into private editor state. Pi's manager supports existing action IDs; its definitions are fixed at construction. `registerShortcut` registers a literal key combination, and TypeScript declaration merging does not add a runtime action definition.

Use the supplied manager's public user-binding information to identify explicit overrides. For example, clearing `tui.editor.undo` suppresses the extra Cmd+Z alias as well as the native default key. Suppressing a raw Cmd+V alias does not suppress terminal-generated bracketed paste; that payload still follows Pi's paste route.

| Behavior                                                                | Configuration contract                                                                                                                                                                                             |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Native movement, deletion, history, yank, undo, newline, and submission | Follow the effective Pi action bindings.                                                                                                                                                                           |
| Native clipboard paste                                                  | Follow `app.clipboard.pasteImage`, including user overrides; the default native route is Ctrl+V.                                                                                                                   |
| Copy selection                                                          | Use the existing `tui.input.copy` action when native dispatch delivers it to the composer. Preserve parent interrupt/clear behavior and the existing Cmd+C convenience.                                            |
| Select all, cut, redo, source-view toggle                               | Document fixed Cmd+A, Cmd+X, Cmd+Shift+Z, and Cmd+Shift+M shortcuts. These actions have no configurable native action IDs in the inspected host.                                                                   |
| Cmd conveniences for native actions                                     | Reuse the corresponding operation only when its native action has no explicit binding override. Yield to other effective native bindings and accepted extension shortcuts. Document these keys as package aliases. |

Neither Pi nor the composer automatically imports macOS text-field preferences. Native `/hotkeys` remains the source for host actions and registered extension shortcuts; direct composer aliases need explicit documentation because they are not native registrations.

## Terminal delivery and capability evidence

The inspected environment is Ghostty 1.3.1, build 15212, on local macOS. Native source evidence is Pi 1.1.0 at commit `6fb2e7815167e6b19006fc526d1a5d0f5f998787`; the workspace fixtures use Pi 1.0.2. Verification must identify which host build and terminal configuration produced each result.

The installed Ghostty configuration consumes Cmd+A, Cmd+Enter, and Cmd+Up/Down with their Shift variants for terminal actions. Cmd+C and Cmd+Z/Cmd+Shift+Z are conditional: whether they reach Pi depends on terminal selection or available terminal undo/redo. Cmd+V ordinarily invokes terminal paste, which can deliver text without a raw Cmd+V event. Cmd+X has no corresponding binding in the inspected configuration. These are findings for that configuration, not universal terminal defaults; [Ghostty's binding rules](https://ghostty.org/docs/config/keybind) define conditional `performable` behavior.

Text delivered through bracketed paste does not carry copied-file identities or image data. The native clipboard action supplies that separate route. A text paste therefore cannot establish image/file shortcut support, and a synthetic Cmd+A event cannot establish physical Cmd+A delivery.

Any claim of automatic terminal integration must satisfy all of these independent requirements:

| Requirement                                             | Verified limitation and evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identify the requesting terminal independently of focus | The installed AppleScript terminal class exposes ID, name, and working directory. [Upstream TTY/PID support](https://github.com/ghostty-org/ghostty/pull/11922) adds process-to-terminal identification, but its merge does not establish availability in the installed build. Detect the actual capability; title, working directory, and focus cannot uniquely identify Pi's terminal.                                                                                                |
| Scope actions to that terminal                          | [Ghostty tables belong to a surface](https://github.com/ghostty-org/ghostty/blob/v1.3.1/src/Surface.zig#L272-L279), and activation targets it. Pane scoping alone does not identify which application owns the terminal.                                                                                                                                                                                                                                                                |
| Release and reacquire during terminal handoffs          | Pi's [suspend](https://github.com/earendil-works/pi/blob/6fb2e7815167e6b19006fc526d1a5d0f5f998787/packages/coding-agent/src/modes/interactive/interactive-mode.ts#L4438) and [external-editor](https://github.com/earendil-works/pi/blob/6fb2e7815167e6b19006fc526d1a5d0f5f998787/packages/coding-agent/src/modes/interactive/interactive-mode.ts#L4596) paths directly stop and restart the TUI. Public session events do not expose these handoffs; process liveness is insufficient. |
| Remove only the integration's changes                   | Ghostty [pops the top table or clears the stack](https://github.com/ghostty-org/ghostty/blob/v1.3.1/src/Surface.zig#L5865-L5893). [Configuration reload clears all tables](https://github.com/ghostty-org/ghostty/blob/v1.3.1/src/Surface.zig#L1726-L1735), invalidating a remembered activation flag. These operations provide no owner-specific removal handle.                                                                                                                       |
| Forward the intended input                              | Named-table `unbind` does not reliably suppress an outer binding in the inspected implementation; [issue 11352](https://github.com/ghostty-org/ghostty/issues/11352) tracks this behavior. Configuration syntax validation is not a forwarding test.                                                                                                                                                                                                                                    |
| Preserve behavior after abnormal termination            | A process killed without cleanup cannot execute an extension shutdown handler. Normal shutdown coverage alone does not establish restoration.                                                                                                                                                                                                                                                                                                                                           |

The inspected capabilities do not establish automatic scoping that satisfies the terminal-ownership ADR. The spec revision must state this limit without claiming that a pane table, a configured binding, or successful syntax validation guarantees Pi-only behavior. Editing corrections remain independently actionable through input that reaches Pi.

## Acceptance plan

Use the existing public editor/session seam with the actual packages. Exercise both views and record visible draft content, selection effects, exported Markdown, native actions, and history results. Source inspection establishes the gaps above; it does not replace behavioral verification.

| Boundary                 | Required checks                                                                                                                                                                                                                                                                                                                         |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native editing           | Exercise default and customized word/line deletion, forward/backward deletion, newline joins, empty boundaries, retained-text recovery, and undo/redo. Include punctuation, whitespace, emoji, combining characters, code, and formatted text.                                                                                          |
| Navigation and selection | Check logical versus wrapped lines, short/long visual rows, repeated top/bottom movement, prompt-history boundaries, and anchored Shift movement. Verify select-all through redraw, resize, view changes, and attachment preview refresh.                                                                                               |
| Binding precedence       | Bind native editing actions to composer alias keys and verify the configured action wins once. Change and clear native bindings to verify alias suppression. Exercise accepted extension shortcut conflicts, native application reservations, explicit history bindings, undo overlapping picker keys, and focused picker/overlay keys. |
| Shared state             | Verify edits and selection replacements through native text APIs and external-editor return. Undo must restore text and attachment membership without changing stored snapshots or another session's history.                                                                                                                           |
| Paste and attachments    | Exercise terminal text paste separately from native clipboard text, files, and images. Use the configured clipboard action, with and without `pi-composer`, and with effective listeners and overrides. Verify the existing native widget coexists with keyboard selection.                                                             |
| Skill completion         | Verify native completion providers and extension-owned pickers that insert through public Pi text APIs, provider updates, keyboard acceptance/cancellation, and canonical reference edits through the same draft history.                                                                                                               |
| Physical Ghostty input   | Begin with unmodified effective terminal settings. Record each gesture's observed route and result, including terminal selection present/absent and terminal undo available/unavailable. Preserve useful Cmd+Delete and Cmd+Arrow translations.                                                                                         |
| Terminal ownership       | Verify that switching panes, entering an external editor, suspending/resuming Pi, reloading extensions or terminal configuration, and exiting preserve surrounding terminal behavior. Any runtime scoping claim additionally requires coexistence with another key table and abnormal-termination checks.                               |

Physical checks must include Cmd+A, Cmd+C/X/V, Cmd+Z/Cmd+Shift+Z, Cmd+Enter, Cmd+Delete, Option+Delete, Cmd+Left/Right, Cmd+Up/Down, shifted movement, and extra Up/Down at the draft boundaries. A failure must identify whether the terminal consumed the key, Pi routed it elsewhere, or the composer produced the wrong edit. Test another terminal only before making a support claim for it.

## Revision and implementation order

1. Revise the composer spec around native action resolution, deletion/recovery, boundary movement, anchored selection, fixed aliases, and delivery limits. Link the keyboard ADRs and replace ambiguous shortcut guarantees with the contracts above.
2. Revise the paste, attachment, and skill-reference specs at their shared input and focused-UI boundaries. Align the library notes, README, and terminal acceptance procedure.
3. Implement missing native editing operations against the shared draft and history, then correct boundary navigation and shortcut precedence. Preserve host-owned application and viewport behavior.
4. Verify through the public Pi boundary, then run the physical Ghostty checks and record delivery limits separately from editor results.

## Native implementation evidence

- The [composer input handler](../packages/pi-composer/src/source-editor.ts) owns its draft operations, and [projection](../packages/pi-composer/src/projection.ts) maps logical positions and visual rows. Current handlers omit word/line deletion and clamp vertical movement to the current column at the outer rows.
- Pi's [native action definitions and manager](https://github.com/earendil-works/pi/blob/6fb2e7815167e6b19006fc526d1a5d0f5f998787/packages/tui/src/keybindings.ts) define effective action IDs and configuration behavior. Its [editor](https://github.com/earendil-works/pi/blob/6fb2e7815167e6b19006fc526d1a5d0f5f998787/packages/tui/src/components/editor.ts) supplies the reference behavior for line boundaries, prompt history, deletion, and yank.
- Pi's [custom editor dispatch](https://github.com/earendil-works/pi/blob/6fb2e7815167e6b19006fc526d1a5d0f5f998787/packages/coding-agent/src/modes/interactive/components/custom-editor.ts) preserves application and explicit-history priority. Its [extension runner](https://github.com/earendil-works/pi/blob/6fb2e7815167e6b19006fc526d1a5d0f5f998787/packages/coding-agent/src/core/extensions/runner.ts) resolves accepted shortcut registrations, and [extension interfaces](https://github.com/earendil-works/pi/blob/6fb2e7815167e6b19006fc526d1a5d0f5f998787/packages/coding-agent/src/core/extensions/types.ts) expose literal shortcut registration and session events.
- The [attachment preview implementation](../packages/pi-attachments/src/images.ts) already uses Pi's public widget API and native `Image` component. Keyboard acceptance must preserve editor focus and selection when previews redraw.
