# Independent composition extensions

Editing, attachments, and skill references are separate Pi extensions with separate packages and specifications, so attachment and skill behavior remain useful with the native editor when `pi-composer` is absent. `pi-attachments` owns paste classification and attachment capture in distinct internal modules that share one capture, recovery, and storage operation, keeping a pasted attachment within one package lifecycle. Cooperation with other extensions follows Pi's existing native contracts and the active editor's draft-transaction ownership.

The attachment integration uses released Pi packages, preserves the selected editor, and keeps `pi-composer` optional. The scoped editor-instance adapter in [ADR 0002](0002-one-editor-owns-draft-transactions.md) passed separate native-editor and composer compatibility checks; it does not permit silently replacing the native editor. Keep verifying attachment-only and combined installations through the same editor/session boundary. The completed host rollback and controlled runtime checks are recorded in the [portability ticket](../../.scratch/pi-attachments-settings/issues/07-verify-portability-and-restore-pi.md), with physical terminal acceptance still open; unrelated package behavior and retained data remain preserved.
