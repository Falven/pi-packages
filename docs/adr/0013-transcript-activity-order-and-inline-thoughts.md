# Preserve activity order and inline thought placement

`pi-chat` groups consecutive activity items and execution activity items across assistant messages, stopping at visible non-tool items or explicit boundaries. [Tool calls and execution cells can produce several rows](0019-tool-renderers-own-tool-presentation.md) without imposing group boundaries. Pi's native `hideThinkingBlock` removes reasoning rows completely when true; when false, full native thought prose appears inline without its own header, viewport, or disclosure. This preserves Pi's visibility choice and [native content ownership](0012-transcript-preserves-native-content.md) without a new setting or raw-versus-summary distinction.

## Consequences

Omitted reasoning does not split render groups; visible commentary and meaningful boundaries still do. Live, retained, and pre-compaction reasoning follow the same rule. Standalone bold activity headings are omitted from displayed prose; inline emphasis and canonical source remain intact. [Find](0016-search-retained-transcript-content.md) can temporarily reveal its selected hidden occurrence without changing Hide thinking.

Working labels follow the [installed desktop app's current-operation rules](../plans/working-label-parity.md), independently of thought visibility. Select current operations through the existing generic activity interface, otherwise the latest complete activity heading (the thought title), with `Thinking` as the default. Reuse the heading already extracted from thought presentation. Body prose, inline emphasis, code samples, and incomplete headings cannot supply a label or replace an earlier title. Preserve the title across body streaming and thinking/message completion; an agent activity ending, a new delivered request, or session replacement clears transient state. Fit the fullscreen indicator to one line with an ellipsis when needed. When no current operation supplies a label, a confirmed final answer hides the working indicator using existing phase evidence. This corrects the earlier last-reasoning-line rule: the app's summary-text helper is not a title extractor for a whole Pi thought. It changes presentation without adding prompts, generating titles, or requiring another extension.

The current render group's displayed header is the single thinking row: the native loading indicator, selected working label, and trailing disclosure chevron. The label can be a current operation, the latest complete activity heading, or `Thinking`, under the existing selection rules. Determine the row's destination independently from the current agent activity and established projected group boundaries; a selected operation alone does not keep an earlier group current. Other retained groups use their aggregate summaries. Without a current displayed group header, the same live row appears below the conversation without a chevron. Preserve native indicator lifecycle, thought visibility, grouping, and disclosure choices while removing the duplicate editor/status placement. This [specified working-row revision](../specs/pi-chat.md) replaces the earlier operation-only header restriction; implementation and verification are tracked in [Chat 18](../../.scratch/pi-chat/issues/18-active-accordion-working-row.md).

Pi exposes requested delivery mode at input submission, but later handlers and expansion can change or consume the input before both queues construct ordinary user messages without a delivery identifier. The [runtime adapter](0022-native-rows-in-an-owned-transcript.md) observes the actual message objects passed to the initial prompt and returned by each queue's drain, recording delivery only when that user message starts and joining it to its persisted entry afterward. [Relationship metadata](0017-native-transcript-relationship-metadata.md) preserves these established boundaries; where historical delivery provenance is missing, only the uncertain agent activity relationships remain expanded, without inventing boundaries or disabling tool disclosures, inline thoughts, or search.
