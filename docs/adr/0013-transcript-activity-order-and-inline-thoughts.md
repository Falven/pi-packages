# Preserve activity order and inline thought placement

`pi-chat` groups consecutive top-level tool calls across assistant messages, ending groups at standalone non-tool items or explicit boundaries; steering separates groups within the current work history, while a queued follow-up starts a new one. Thoughts appear in source order as native Markdown in ordinary chat flow, with spacing around adjacent tool groups and [native content ownership](0012-transcript-preserves-native-content.md). A standalone bold paragraph anywhere in a thought becomes a transient label through Pi's native `ctx.ui.setWorkingMessage` indicator and is omitted from displayed thought prose; inline bold emphasis remains prose, the canonical message is unchanged, and no custom spinner is added. Thoughts have no separate header, viewport, or toggle; the enclosing work-history fold still applies.

## Consequences

Pi exposes requested delivery mode at input submission, but later handlers and expansion can change or consume the input before both queues construct ordinary user messages without a delivery identifier. The [runtime adapter](0022-native-rows-in-an-owned-transcript.md) observes the actual message objects passed to the initial prompt and returned by each queue's drain, recording delivery only when that user message starts and joining it to its persisted entry afterward. [Relationship metadata](0017-native-transcript-relationship-metadata.md) preserves these established boundaries; where historical delivery provenance is missing, only the uncertain work relationships remain unfolded, without inventing boundaries or disabling tool disclosures, inline thoughts, or search.
