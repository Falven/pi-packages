# Tool renderers own tool presentation

`pi-chat` forms render groups from [consecutive tool calls](0013-transcript-activity-order-and-inline-thoughts.md) without depending on their summaries. Every top-level call is eligible; visible standalone non-tool items and explicit activity boundaries separate groups, while omitted reasoning does not. Pi and each tool's existing renderer still own expanded call and result presentation.

Execution status belongs to its native tool presentation and collapses with that tool's render group and agent activity, while the final response remains separate. For `pi-codex-tools`, `pi-chat` targets the native `exec` presentation described in [ADR 0024](0024-core-tools-use-native-extension-lifecycle.md), with routine execution journals invisible as standalone chat rows. Associating continuing execution status with its initiating call remains the tool renderer's responsibility; `pi-chat` does not interpret `core-tools.activity` data or add compatibility code for the earlier standalone journal presentation.

One group-summary module uses observed public built-in provenance and execution events to give collapsed groups normalized action descriptions. Built-in reads, searches, and lists become “Read files”; edits and writes become “Edited a file/files”; shell calls become “Ran a command/commands”; recognized skill-definition reads become “Loaded a tool/tools.” Unknown or replacement calls remain “Called a tool/tools.” Active group headers use present-tense summaries from observed execution, separately from thought working messages. This limits inference to reliable built-in facts, leaves older calls with uncertain provenance generic, and requires no renderer scraping, shell parser, tool exclusions, new protocol, or persisted summary metadata.
