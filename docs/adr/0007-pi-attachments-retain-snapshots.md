# Retain attachment snapshots

`pi-attachments` preserves captured attachment contents and keeps existing snapshot paths and recovery records readable, while plain source paths identify current source files. Generated image filenames include their format extension so the system selects the associated application; previews and their filename fallbacks link to the retained full-resolution file through Pi's native hyperlinks and system handler, including the ability of an external application to save changes to that file. Every snapshot added to a draft remains available for undo histories, saved drafts, submissions, and forks; explicit cleanup reclaims only proven-unused capture or staging data because Pi's public interfaces cannot enumerate every live history or session location.

Markdown links and images pointing to local regular files express attachment membership, including reference-style links and local file autolinks. Code, escaped examples, unused link definitions, and remote URLs do not establish membership. Stripping the link markup leaves ordinary path text; restoring a link to retained contents reuses those contents without a new capture. Removing a reference from a draft does not delete its retained file.

Attach…, recognized file-path pastes, and newly valid local-file Markdown references capture when added to the draft. After successful capture, an authored reference's destination changes to the retained snapshot; its first preview, later previews, and submission reuse that snapshot. Capture follows the reference independently of image visibility, while redraws, resizing, and settings changes never create new snapshots. Later source changes do not affect the captured attachment, and ordinary edits to bare paths do not capture contents. Automatic destination replacement must preserve the active editor's draft, selection, and undo contracts; its editing behavior still requires a usability check.

Attachment snapshots and recovery records persist independently of Pi's session files, including when Pi runs with `--no-session`. Disabling session-file persistence does not change attachment retention; an ephemeral attachment mode would require a separate lifecycle contract that preserves recovery and reference validity.
