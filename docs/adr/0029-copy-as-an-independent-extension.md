# Copy decorates native output as an independent extension

`pi-copy` and `pi-chat` are independently installed Pi extensions. Neither imports, depends on, or installs the other. Copy attaches its existing command, output, diff, and final-response controls to native Pi presentation; when chat owns the transcript, an optional in-process agreement supplies the same controls with chat's authoritative activity and final-response sources. This supersedes [ADR 0026](0026-copy-actions-in-a-dependent-package.md): moving code into a library did not provide independent use.

Copy owns control creation, native panel decoration, payloads, clipboard work, feedback, and disposal. The active transcript owner supplies source identity and integrates control geometry with its existing focus, selection, and layout. Chat keeps its activity grouping, final-response recognition, and source Find. Both extensions discover the optional agreement through Pi's existing event bus after extension registration, so load order does not select behavior and only one adapter attaches controls.

The native adapter preserves Pi's existing components and rendering. This is a scoped exception to [ADR 0001](0001-preserve-pi-extension-contracts.md): Pi 1.1.0 has no public hook for these inline controls. A synchronous observation of the public widget call acquires the current host and restores its observer immediately. Decoration, selection, and Find hooks attach to the existing component and renderer instances, check required capabilities, and remain reversible. Keep these hooks inside copy, restore them on reload/shutdown, and verify native-only and combined installations. No second transcript, shared runtime package, or dependency fallback is introduced. The retained-source and display-only spacing rules in [ADR 0027](0027-copy-retained-source-and-separate-presentation.md) remain authoritative.
