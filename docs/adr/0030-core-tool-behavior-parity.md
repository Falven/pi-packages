# Core tool behavior follows the scoped reference

The 2026-10-17 comparison found different model inputs and filesystem effects behind matching tool declarations. The user requested six corrections: cell termination, argument validation, shell fallback, JavaScript failures, patch deletion effects, and image detail. Adopt the behavior of the captured Codex `0.163.0-alpha.10.2` for those boundaries, and verify ordered results, actual file effects, and delivered images through both real hosts. Matching final answers alone does not establish this contract.

Pi must remain unchanged. On 2026-10-18 the user rejected the proposal to extend Pi's public image contract and said, "You are not allowed to modify Pi under any circumstance." Use extension-owned code and Pi's existing public APIs. Do not change Pi source, installed packages, private runtime behavior, or version requirements to obtain new host behavior. An unresolved difference must remain visible; it does not authorize a Pi modification.

Cell termination must stop the coordinating program without implicitly killing an already-running command. Process interruption and session cleanup remain separate controls. Termination must prevent new work from the ended program, retain ownership of live processes for cleanup, and preserve factual late outcomes. Queued and in-progress non-process operations need the reference checks specified in the plan before their cancellation behavior is changed.

Use Pi's public argument-preparation hook to enforce the reference's field-specific types, defaults, null handling, and unknown-key rules before Pi can coerce values. Keep normal dispatch, permission hooks, argument edits, and result processing. Preserve the frozen scoped model declarations; do not add guidance to compensate for runtime differences. Include native failure framing and genuine source stack information, and disclose any unachieved parser or runtime fidelity rather than hiding it through comparison normalization.

The user accepted Q3 on 2026-10-18. For an explicit shell argument, our command tool will follow Codex's full selection rule: infer the kind of shell from the supplied name, find an installed program of that kind, and use the platform fallback if necessary. The supplied path is not a guarantee that its exact file runs, even if that file exists. Custom startup scripts can therefore be skipped. When the argument is omitted, keep Pi's configured shell and command prefix. Implement this inside our extension; Pi remains unchanged.

Patch application must preserve the reference's ordered partial effects. If deleting a target makes a later symlink dangling, fail that later deletion, retain the link, preserve the earlier deletion, and report completed, failed, and unattempted changes accurately. Do not roll back the earlier deletion or turn the failed step into a successful unlink.

The user accepted Q2 on 2026-10-18 and asked for our own image handling. Core-tool image preparation will belong to `pi-codex-tools`: preserve the requested detail, apply Codex's image limits and format rules, and supply the corresponding bytes and provider metadata. Pi's automatic resize preference must not determine the final core-tool image. Original detail still follows Codex's limits and can require resizing above them. Image blocking and other extensions' image removals or replacements remain effective. The earlier image exception in [ADR 0024](0024-core-tools-use-native-extension-lifecycle.md) does not satisfy this outcome.

Use Pi's existing finalized-message and provider-request hooks to integrate that preparation. The eight-case probe preserved original PNG bytes through history reload and respected tested image edits and blocking. This does not bypass all Pi image work: the installed host still normalizes real image blocks after result hooks and exposes its resized result in `tool_execution_end`. There is no per-tool or per-image skip option in the inspected public contract. Replacing the finalized message can control history and model input; verify the remaining event and display consumers separately. Do not hide images from normal result hooks to evade normalization, change global settings, or modify Pi.

The public-hook prototype is not a complete production solution. It relies on an observed result-event lifetime and does not cover all formats, detail modes, or activity bindings. Resolve those limits before integration and compare the actual encoded bytes. Reuse existing image primitives only where their behavior matches the reference; owning preparation does not require writing an image codec or a second provider integration.

Q1, Q2, and Q3 are settled: Pi stays unchanged, core-tool images follow Codex's preparation rules, and explicit shells follow Codex's full selection rule. The user requested publication in the [existing specification](../../.scratch/core-tools/spec.md) on 2026-10-18. This accepts the requirements and boundaries; it does not certify the prototype, runtime implementation, or full parity. The [implementation plan](../plans/core-tool-behavior-parity.md) records the affected surfaces and remaining evidence gates. The original public lifecycle, independent presentation, retained-history, and permission boundaries remain in force except where this revision explicitly revisits them.
