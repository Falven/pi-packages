# Core tools use the native extension lifecycle

The user requested a further behavior correction on 2026-10-18 and prohibited changes to Pi under any circumstance. [ADR 0030](0030-core-tool-behavior-parity.md), the [updated specification](../../.scratch/core-tools/spec.md), and the [implementation plan](../plans/core-tool-behavior-parity.md) revisit cell termination, argument preparation, explicit shell selection, failure output, patch deletion effects, and model-bound image detail. The paragraphs below record the earlier implemented policy; the accepted revision does not claim those corrections are already implemented. Q2 accepts extension-owned image preparation under Codex's rules. Integrate it through existing public extension APIs while retaining public dispatch, blocking and result hooks, and session cleanup. The earlier proposal to extend Pi's image contract was rejected.

The core toolset uses Pi's public registration, dispatch, and lifecycle without changes to Pi's source; session-owned cells retain their workers across yields and record compact activity through public custom entries because native nested-call history ends with the parent. Live commands, cells, and temporary values survive ordinary prompts, while session replacement or reload stops owned work and clears temporary state without erasing file changes or retained history. Package-owned identity and explicit cancellation preserve continuation but accept differences in native hook identifiers, runtime attribution, and notification delivery instead of adding a private lifetime adapter.

Model-facing core tool guidance comes verbatim from the frozen, scoped reference contract. Remove local additions and paraphrases; selection can omit unavailable tool sections but cannot rewrite the retained wording. Record host limitations in operator documentation rather than injecting extra guidance into the agent interface. Do not add instructions about read style, batching, or shell formatting. ChatGPT.app/Codex system prompts and other prompts are outside this contract and this alignment work.

Each operation's progress, accumulated text, and late failures remain associated with the execution that started it; `wait` calls do not duplicate that text. The chat presents operations in separate rows with independent details, so lifecycle ownership does not force all commands or changed files into one `exec` card. Images use the approved native-display exception: their path and status remain in the origin, while the actual image appears once in the result that collects it, including a later `wait`. Pi's public renderer API cannot relocate the native shell's result images independently of content, so this preserves normal hooks, image processing, preferences, and model input without private UI changes or duplicate payloads. Orchestration source and transport metadata remain in retained history. Routine activity records remain invisible in the chat view and reconcile the latest recorded status after reload, so a later completion overrides an earlier running record. This preserves the operation's ownership across prompts without duplicating an operation when it updates, adding automatic failure notifications, or starting unsolicited model turns.

Live command presentation uses process output and lifecycle events, independently of model output collection, with Pi's screen-refresh batching and no display-driven polling or extra tool calls. Returned results still pass through Pi's normal result hooks. Live output may be visible before those hooks run, and later redaction cannot undo that visibility.

The toolset publishes stable operation identities, effective inputs, per-operation outcomes, and available output through the documented activity data format. It constructs these facts locally without a contract package or dependency on any chat consumer. Consumers independently validate the same format without knowing tool names, package paths, or private execution records. The toolset works without any chat consumer and an unrelated consumer can subscribe to the same facts. Raw execution text remains in model results and retained source; publishing text is not a new operation. Execution errors remain factual, separate from child outcomes, including failures before any child starts. Output ownership follows its source; matching text alone does not establish that ownership. Compact operation and per-file change facts survive limits on retained detail output; truncating a body must not delete its operation.

Patches validate every operation before writing, then apply operations in order against the current file contents while holding the existing public file mutation queues. Validation snapshots cannot supply later replacement contents or change facts: an earlier operation may have changed the same file through an alias or move. Initial validation failures leave files unchanged; application-time failures preserve completed changes and report failed and unattempted operations accurately. This retains the selected partial-failure behavior without adding rollback or cross-process locking.

Consumers derive their presentation from those facts under [ADR 0019](0019-tool-renderers-own-tool-presentation.md). Input and collection emit no new action, including when they fail; submitted terminal commands update the original operation's actions. Script errors remain in model results and retained source without being published as operations. This avoids duplicate tool/script error rows without changing rejection values or inferring their identity. Retained updates and live events use the same versioned contract and reconcile by originating call, session, and revision. Processed result content is authoritative: missing or invalid bindings fall back to that result rather than reviving discarded journal bodies. The provider's lifecycle ownership does not define the visible row or require a shared control. Its standalone renderer remains independent of chat.

The process-input correction follows the installed app's Codex `0.162.0-alpha.17.2` implementation: an exact Ctrl+C input (`\u0003`) interrupts a non-terminal process through its process group; other nonempty input still requires a terminal. Preserve existing terminal input, collection serialization, output cursors, observed outcomes, and process ownership. This is the approved runtime exception to the earlier presentation-only scope. It does not alter the frozen tool declarations or add model guidance. The [reference plan](../plans/core-tool-activity-alignment.md) records the source and remaining validation limits.
