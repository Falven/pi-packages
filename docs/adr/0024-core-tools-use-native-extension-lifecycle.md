# Core tools use the native extension lifecycle

The core toolset uses Pi's public registration, dispatch, and lifecycle without changes to Pi's source; session-owned cells retain their workers across yields and record compact activity through public custom entries because native nested-call history ends with the parent. Live commands, cells, and temporary values survive ordinary prompts, while session replacement or reload stops owned work and clears temporary state without erasing file changes or retained history. Package-owned identity and explicit cancellation preserve continuation but accept differences in native hook identifiers, runtime attribution, and notification delivery instead of adding a private lifetime adapter.

Each operation's progress, accumulated results, and late failures belong to the `exec` card that started it; `wait` cards do not duplicate its output. Compact action summaries expand into underlying operations and readable results, while orchestration source and transport metadata remain in retained history. Routine activity records remain invisible in the chat view and reconcile the latest recorded status after reload, so a later completion overrides an earlier running record. This preserves the operation's ownership across prompts without creating duplicate chat rows, automatic failure notifications, or unsolicited model turns.

Live command presentation uses process output and lifecycle events, independently of model output collection, with Pi's screen-refresh batching and no display-driven polling or extra tool calls. Returned results still pass through Pi's normal result hooks. Live output may be visible before those hooks run, and later redaction cannot undo that visibility.
