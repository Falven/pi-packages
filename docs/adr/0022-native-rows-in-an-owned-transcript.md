# Compose an owned chat view from native Pi components

To obtain exact occurrence targeting, `pi-chat` borrows Pi's existing message components through one in-process adapter and projects tool activity into [activity items with independently expandable native output controls](0019-tool-renderers-own-tool-presentation.md). Pi retains conversation data, component updates, the composer and dock, terminal protocols, and final painting; the extension owns chat composition, logical viewports, selection across those viewports, and retained-source search. This accepted architecture permits private runtime integration as the scoped exception in [ADR 0012](0012-transcript-preserves-native-content.md) and [ADR 0014](0014-fullscreen-transcript-interaction.md). Pi 1.1.0 and later are the primary target. Compatibility checks require the functions the adapter uses, rather than a particular version string. Pi's source files remain unchanged.

## Considered Options

A public overlay can host a supplemental transcript reader, but leaves native chat painting active and does not supply native scroll-region selection or complete replacement of image rows. Duplicating active custom tool renderers would duplicate their state and side effects. Borrow native components where their presentation matches the required view; activity-item projections use default native or generic activity bodies instead of duplicating an extension's custom renderer. Unsupported host integration remains in one internal module.

## Consequences

The earlier output-padding gutters, native output sizing, and global disclosure revision was implemented on `codex/chat-scroll-integration`. [Chat 12](../../.scratch/pi-chat/issues/12-mixed-session-acceptance.md) records its checks on Pi 1.1.0 and 1.0.2, review results, physical cmux observations, and remaining physical limits. Independent native previews were subsequently implemented at `39e0e5d` and verified through the native host on both versions. That ticket records the current checks and reviews separately from earlier physical observations; no new physical-terminal check was performed.

- **Host ownership.** Capture the actual `InteractiveMode` through a scoped observation of the native widget method, reached through `ctx.ui.setWidget`, and restore the prototype descriptor immediately. Save and replace the host's `fullscreenLayoutRoot`, reusing its layout entries, sizing, gap, and alignment while replacing only its transcript slot. Preserve the exact existing pending-message, status, widget, editor, and footer containers, including additional native layout children. Leave the native document, chat container, and event reducer intact. Regular mode and transcript-on-exit continue through Pi's original document.

- **Bootstrap.** During normal reload and session replacement, Pi can rebuild history before `session_start`. Arm a temporary `renderSessionEntries` prototype observer during extension initialization, recognize the exact owning runner through the registered relationship-entry renderer's function identity, install the instance adapter before native construction, and restore the prototype descriptor. At `session_start`, disarm any remaining observer and use the widget capture for an initial TUI start. Require `ctx.mode === "tui"` and the same session manager. This targets Pi's normal CLI lifecycle; abandoned extension discovery in custom SDK resource loaders has no corresponding disposal guarantee and is outside this design.

- **History binding.** Call the original `renderSessionEntries` with a shallow array referencing the original entries. Observe its entry-local `flatMap` projection on that array, pairing actual projected items with their source entry and item ordinal without modifying entries or copying Pi's projection rules. Pass the resulting items through a scoped iterator to the original `renderSessionItems`, preserving native selection reset, options, notices, and component construction. Restore the scoped method in `finally` and fail explicitly if items cannot be associated. This still depends on Pi's `flatMap`-then-`renderSessionItems` construction path. Observe container insertions and native removal paths; retain otherwise-unpersisted notices by component identity and insertion position. Bind custom-entry components to their actual source entries whether Pi appends them or inserts them before a streaming assistant component. Source identity alone does not establish agent activity membership. No extra history rebuild or text matching is needed.

- **Component ownership.** Map assistant content indices and thinking runs to the children created by native rendering, rebinding those references after native assistant updates. Preserve native semantic terminal markers when composing those children. Each activity body component keeps stable operation identity and source references, and image instances have one visible owner. A projected operation and its original aggregate card are not both displayed. Missing historical rows use the native factory methods with a detached destination and editor-history population disabled. Only when thinking is visible or a hidden thought is selected by Find, otherwise-absent thought bodies use native assistant construction with a render-only array referencing the original thought blocks and the current Markdown environment. Normal hidden rendering does not construct thought bodies. Pi's public `registerMarkdownTransformer`, restricted to assistant thinking, omits standalone bold activity headings from display while leaving inline emphasis, original blocks, and native presenter identity intact. Historical tool presenters follow native history initialization and current output padding, without starting execution or speculative edit previews. None of these projections enters conversation history.

- **Thinking visibility.** Honor Pi's native `hideThinkingBlock` with no new setting or raw-versus-summary distinction. True omits thought rows, placeholders, headers, spacing, and disclosures; eligible tools group across omitted reasoning while visible commentary and meaningful boundaries still split groups. False preserves full inline native prose apart from extracted activity headings, and visible thoughts split groups. Live, retained, and pre-compaction reasoning follow the same policy; source and searchability remain unchanged. All groups, including singletons, inherit the current global expansion state under ADR 0020. Expanding disclosures does not change Hide thinking or final-response visibility. Provider and model controls remain with Pi.

- **Working label.** Pi's native working-message API is one shared slot without an owner or getter. In either Hide thinking mode, update it only when the displayed working label changes and clear it only after this extension has set a label; do not arbitrate writes from other extensions or add an ownership mechanism. Public assistant/tool lifecycle events and the validated generic activity facts feed the selector. Within the current activity slice, prefer the latest running read/search/list in a trailing exploration, otherwise its latest read/search/list; outside exploration, prefer the latest running operation. Use the latest complete activity heading, then `Thinking`, when no operation qualifies. Reuse the thought-presenter's extraction; never select or summarize body prose. Body streaming and reasoning/tool-result completion do not clear the title. During fullscreen layout, fit the selected text to its actual destination's available terminal cells, accounting for the native spinner, padding, and trailing disclosure chevron when present. Collapse whitespace, truncate with an ellipsis, and recompute on resize without changing the source label. Existing provider-phase reconciliation suppresses the working indicator for a confirmed final answer with no current operation, using Pi's public visibility setter; reset restores the native default. Retained history cannot start a live indicator. Pi retains native indicator creation, animation, and disposal. Under the specified working-row revision, the fullscreen host borrows only the working presentation for one current group header or standalone conversation row, detaching duplicate editor/status placement before dock measurement. Moving it must not dispose it; reconcile editor replacement and restore native placement only while still owned when releasing the fullscreen view. Retry, compaction, and other status indicators keep native presentation. [The source record](../plans/working-label-parity.md) fixes the reference version, the corrected input mapping, and boundaries.

- **Render-group summaries.** Adapters owned by `pi-chat` normalize built-in and extension facts into operations under ADR 0019. The group-summary module aggregates their types in fixed order; group eligibility and disclosure state remain independent of wording. Source references share observed state across native settings reconstruction within the same load. Reliable retained provider facts can reconstruct operations; uncertain historical provenance keeps the generic fallback. Operation lifecycle facts drive active wording, including continuing operations after the parent call returns. Missing results do not establish a running operation, and a parent failure does not establish a child failure. Summaries and working labels independently consume those facts; summaries do not write the working-message slot, message source, or persistent relationship entries.

- **User-message alignment.** Fullscreen chat renders the native `UserMessageComponent` at the native chat width, retaining its themed background bar, existing output padding, and Markdown transformations. That existing side padding serves as the conversation gutters; do not inset the component again. Cell-aware composition uses its native blank padding row for the background and aligns rendered content as one block to the right with native right padding, preserving relative Markdown indentation. Keep OSC 133 markers at the row prefix and translate child pointer coordinates. Search and selection use the displayed aligned rows; copying excludes the conversation gutters and added left alignment margin without removing content indentation. Canonical messages, regular mode, and printed-exit history remain unchanged.

- **Conversation gutters.** Reuse Pi's current `outputPad` as the left and right conversation gutters across the entire conversation viewport, including messages, disclosure headers, and activity bodies. Count this padding once: add no columns, minimum gutter width, or new setting, and do not combine native padding with another outer inset. Zero output padding means no conversation gutter. Wheel movement over this space goes directly to the conversation rather than to child content. Recompute the hit bounds when padding or layout changes. The native scrollbar gutter remains a separate region, and native scrollbar behavior takes priority wherever a scrollbar occupies the edge. The composer, dock, and overlays retain their existing geometry and input priority.

- **Native presentation settings.** Use Pi's current `outputPad` for native components in render-group and agent-activity headers, including the agent activity divider. Let Pi update live presenters and forward changed padding to detached historical presenters through available native setters. Read the mode from Pi's native transcript `ScrollView`, retain its style callbacks, and obtain content width through `getContentWidth()` before layout. Register the owned primary scroller with native layout so `always`, `auto`, and `hidden`, track clicks, dragging, hover, and hiding use Pi's existing implementation. Add no settings, copied defaults, version guard, or private hook. Older Pi 1.0.2 retains its native fixed tool inset and history rebuild behavior.

- **Source identity.** Keep stable presentation handles pointing to live message objects or committed entry/part references. Update a live handle's current object as stream events arrive; promote that same handle after native persistence rather than replacing its disclosure state. Hashes are unnecessary for occurrence identity. Index the raw branch once, reconcile appended entries incrementally, and rebase on session or branch changes. Persist only established relationships in the native custom entries permitted by [ADR 0017](0017-native-transcript-relationship-metadata.md).

- **Delivered requests.** Observe the actual message objects returned by the particular agent's steering and follow-up queue drains, and the message objects passed to its initial prompt operation. Preserve the original calls and return values; record delivery only when the corresponding user message starts. An agent listener ordered after native session persistence joins those objects to committed entries. This avoids input snapshots and text matching, including for identical queued prompts.

- **Disclosures.** Preserve the existing activity order, always-retained group disclosure, inline-thought, and final-response policies in ADRs 0013, 0015, and 0020. Under ADR 0014, Pi's configured global expansion action sets available enclosing disclosures and descendant groups, items, and native output. An enclosing header requires a qualifying final, an uncancelled turn, and renderable collapsible activity. Remove it and reveal activity when eligibility disappears, even after explicit closure; do not retain a revoked header just because it has a preference. Retain the same activity's preference for requalification and leave descendant choices intact. While eligible, explicit choices outrank the automatic default and child-inspection hold. Find records an explicit open choice even during temporary ineligibility. Scrolling, selection, and header focus create no hold. New groups and items inherit the current global state; an action while the enclosing header is unavailable does not overwrite its retained preference. Provider phase, selected final, settlement, eligibility, and preference are separate facts. Exactly associated nonblank final text or explicit provider item completion can qualify; a completed blank final retains its source boundary without synthetic answer text or dropped native notices. A done event alone is insufficient. Valid partial finals can remain eligible after errors; cancellation removes enclosing eligibility. The no-phase fallback still selects qualifying terminal text only after settlement, without prose inference. Choices remain memory-only and reset at the existing reload/session/branch boundaries; existing settled final references restore completed blank selections, while insufficient historical facts stay visible.

- **Standalone extension notices.** An identified standalone extension notice without established agent activity membership stays visible when the surrounding known agent activity closes. It continues to separate render groups but does not by itself prevent composing that agent activity with its known final response. Keep retained user rows and notices in one native-ordered sequence; expanding agent activity restores its activities around those same rows without duplication. A notice alone does not create an empty agent activity disclosure. Preserve actual request and history boundaries, and do not scan across unidentified message rows or pull a notice after the final response ahead of it. Operation status and an execution's own entry follow their activity and agent activity disclosures under [ADR 0019](0019-tool-renderers-own-tool-presentation.md).

- **Layout.** Maintain a logical tree of leaves and disclosures. Expanded render groups expose all activity items in ordinary chat flow; activity bodies use Pi's native preview or expanded size according to the output control's independent state without a group or body height cap, as decided in [ADR 0021](0021-bounded-render-group-scrolling.md). Thought Markdown remains in ordinary chat flow without its own header or viewport. Before a frame, allocate the original dock, measure dirty content at the native content width with output padding counted once, and intersect the native clips. Register the primary native scroller around blank geometry rows, with spacers before and after the visible intervals giving it the full logical chat height. Paint each interval through a native `ScrollView` containing the original uncropped rows, with exact interval height and its own scrollbar hidden; these painting windows do not create independent group or body scrolling. A non-shrinking native `HStack` keeps these windows at terminal width while the outer content clip excludes the native scrollbar gutter; this preserves Pi's full-width image recovery. Only the leaf windows supply image content, so there is one native crop and one presentation location per occurrence. Keep original image reservation rows and let Pi handle image transmission, placement, and terminal diffing. Preserve the first visible occurrence and local row when heights change, or follow the end when the conversation was already following. Preserve any native child scroll state without imposing a new viewport. The geometry retains one blank string reference per logical display row, resizing with height, without copying conversation text or rebuilding a joined rendered transcript.

- **Interaction.** Keep Pi's input decoding, effective keybindings, child pointer handlers, and clipboard transport. Hit testing checks both horizontal and vertical bounds. Wheel movement over either conversation gutter or a disclosure header scrolls the primary conversation viewport directly. Within an expanded activity body, translate pointer coordinates into the original child's rows and offer events to that child first. Native output clicks toggle its preview/full-output state without closing the enclosing item. Item and native-output choices survive settings reconstruction separately, and the configured global action sets both. If native content supplies its own scrolling, preserve it and pass unused wheel movement to the conversation at either boundary. Standard tool cells without an inner viewport scroll with the conversation. Native scrollbar hover, track clicks, dragging, and redraw remain delegated to Pi, including at a gutter edge. Native Page Up, Page Down, prompt navigation, and Find actions target the primary chat viewport, rather than one of its painting intervals. Selection endpoints identify occurrence, rendered row, and terminal cell. Copy traverses displayed content between the endpoints, including a native preview or offscreen rows in fully expanded output; hidden output, conversation gutters, and scrollbar glyphs are excluded. Native line composition constrains highlighting to the content area, preserving the existing output padding and native scrollbar gutter. Preserve native `app.message.copy` and copy-on-select behavior. Ordinary scrolling preserves selection. Collapsing, content-width changes, or changed selected content clears it without postponing the automatic transitions already agreed. Native overlays and composer focus retain priority.

- **Distinct layout positions.** Reading-position restoration must identify the particular displayed occurrence, including layout-only spacing. Before and after spacing around an agent activity require separate stable identities: reusing one component instance for both lets the first-match lookup restore the wrong position. Keep those identities across redraws and preserve the first visible occurrence and local row through actual geometry changes. Manual scrolling through unchanged content must keep its requested position, whether a disclosure or the composer has focus and whether text is selected. Retain native focus, selection, and follow-end policies rather than using them to mask an ambiguous anchor. This corrects the reported collapsed “Worked for” jump under [Chat 14](../../.scratch/pi-chat/issues/14-stable-reading-position.md).

- **Component copying.** Compose only the command/edit controls in ADR 0019 and the settled final-response footer in ADR 0015. Extend existing focus traversal to visible enabled actions and consume action clicks before native body handlers or selection. Copy authoritative source values at activation, independent of unrelated selection, while preserving native global selection-copy behavior. Exclude action labels and feedback from selection and source Find. Keep control identity and row geometry stable through feedback, resize, and redraw; invalidate pending work and clear timers when their components or host are replaced. The native renderers and original conversation stay unchanged.

- **Keyboard disclosure access.** One shortcut registered through Pi transfers focus from the composer to the nearest visible group, agent activity, or tool disclosure; inline thoughts are not toggles. Reuse Pi's configured selector up/down actions to move between disclosures, confirm to toggle, and cancel to return focus to the current composer. When an enclosing header becomes ineligible and disappears, use the existing missing-disclosure lifecycle to return its focus to the composer. Pointer and keyboard toggles cannot bypass eligibility. Keep expansion chevrons visible without an extra arrow. Highlight focused render group headers with Pi's native selection background; agent activity headers have no background and underline only their focused summary. Use Pi's programmatic focus, configured key matching, focused-component dispatch, and overlay focus restoration; native overlays retain priority. This accepted focus interaction operates on the existing chat view and introduces no slash command or separate reader.

- **Search.** Search readable source fields independently of disclosures, retaining references and match ranges rather than a joined corpus. Reuse Pi's search input component with a source-search controller. Selecting a hit opens its enclosing disclosures and expands only the selected native output control, materializes missing historical rows at their source-ordered position without changing Pi's session projection, and reveals the occurrence through the logical viewports. Hidden-thinking hits temporarily reveal only the selected occurrence using native Markdown; navigation or query changes move or remove that reveal, and closing Find removes it without changing Hide thinking. Highlight the matching text when its rendered range can be established reliably. When a tool renderer omits or ambiguously transforms that text, highlight the owning call instead, preserving its presentation. No temporary excerpt or separate search preview is added.

- **Historical uncertainty.** Private observation can establish future delivery relationships but cannot recover provenance never stored. Leave only uncertain agent activity relationships expanded, retaining native order and available tool disclosures, inline thoughts, and search. Do not invent agent activity boundaries, phase metadata, or explanatory chat messages.

- **Invalidation and cleanup.** The owned root forwards invalidation to the saved native root exactly once, then invalidates its own geometry and owned presenters. Frame-local render references avoid rendering a borrowed component twice for measurement and painting. Rebind the painting and input adapters when Pi replaces its renderer during a mode switch. Clear the owned scrollbar's native hiding timer only while the chat root is still owned; preserve a scrollbar retained by a later owner. Mark adapter callbacks inactive, dispose owned selection/search timers and subscriptions, restore only the instance methods and root still owned by this adapter, and release references; do not dispose borrowed native components. Callbacks or wrappers retained by another owner must remain inert after disposal. Check required hooks as they are acquired and report missing function names. Missing hooks or competing chat-root ownership prevent activation; failed attachment restores native ownership. Function presence alone does not establish behavioral compatibility with future Pi changes.
