# Compose an owned chat view from native Pi components

To obtain exact occurrence targeting without replacing tool presentation, `pi-chat` borrows Pi's existing message and tool components through one version-specific, in-process adapter. Pi retains conversation data, component updates, the composer and dock, terminal protocols, and final painting; the extension owns chat composition, logical viewports, selection across those viewports, and retained-source search. This accepted architecture permits private runtime integration as the scoped exception in [ADR 0012](0012-transcript-preserves-native-content.md) and [ADR 0014](0014-fullscreen-transcript-interaction.md). The implementation request adopted this architecture without authorizing changes to Pi's source files.

## Considered Options

A public overlay can host a supplemental transcript reader, but leaves native chat painting active and does not supply native scroll-region selection or complete replacement of image rows. Constructing a second set of active tool components would duplicate renderer state and side effects. Borrowing the original components preserves the effective renderer chain and concentrates the unsupported integration in one internal module.

## Consequences

- **Host ownership.** Target installed Pi 1.0.2 initially. Capture the actual `InteractiveMode` through a scoped observation of the native widget method, reached through `ctx.ui.setWidget`, and restore the prototype descriptor immediately. Save and replace the host's `fullscreenLayoutRoot`, using the exact existing pending-message, status, widget, editor, and footer containers. Leave the native document, chat container, and event reducer intact. Regular mode and transcript-on-exit continue through Pi's original document.

- **Bootstrap.** During normal reload and session replacement, Pi can rebuild history before `session_start`. Arm a temporary `renderSessionEntries` prototype observer during extension initialization, recognize the exact owning runner through the registered relationship-entry renderer's function identity, install the instance adapter before native construction, and restore the prototype descriptor. At `session_start`, disarm any remaining observer and use the widget capture for an initial TUI start. Require `ctx.mode === "tui"` and the same session manager. This targets Pi's normal CLI lifecycle; abandoned extension discovery in custom SDK resource loaders has no corresponding disposal guarantee and is outside this design.

- **History binding.** Replace only the small `renderSessionEntries` assembly step with the same exported `sessionEntryToContextMessages` helper and native usage-notice rules. Pair every actual projected item with its source entry and item ordinal, then invoke the original `renderSessionItems` once through a scoped iterator. That scope remains active while the native reducer constructs direct tool rows and notices, as well as message rows. Observe container insertions and the pinned host's removal paths; retain otherwise-unpersisted native notices by component identity and insertion position. No extra history rebuild or text matching is needed.

- **Component ownership.** Map assistant content indices and thinking runs to the native children created by the pinned rendering algorithm, rebinding those references after native assistant updates. Preserve native semantic terminal markers when composing those children. Tool components, their renderer state, and image instances have one native owner. Missing historical rows use the native factory methods with a detached destination and editor-history population disabled. Otherwise-hidden thought bodies use native assistant construction with a render-only array referencing the original thought blocks and the current Markdown environment. Historical tool presenters follow native history initialization, without starting execution or speculative edit previews. None of these projections enters conversation history.

- **Source identity.** Keep stable presentation handles pointing to live message objects or committed entry/part references. Update a live handle's current object as stream events arrive; promote that same handle after native persistence rather than replacing its fold state. Hashes are unnecessary for occurrence identity. Index the raw branch once, reconcile appended entries incrementally, and rebase on session or branch changes. Persist only established relationships in the native custom entries permitted by [ADR 0017](0017-native-transcript-relationship-metadata.md).

- **Delivered requests.** Observe the actual message objects returned by the particular agent's steering and follow-up queue drains, and the message objects passed to its initial prompt operation. Preserve the original calls and return values; record delivery only when the corresponding user message starts. An agent listener ordered after native session persistence joins those objects to committed entries. This avoids input snapshots and text matching, including for identical queued prompts.

- **Folds.** Preserve the existing activity order, singleton, and final-response policies in ADRs 0013, 0015, and 0020. Provider phase, final-response selection, and work completion are separate facts. Early collapse requires qualifying final-response evidence tied to a normalized content occurrence. When a provider supplies no final phase, the accepted Pi policy treats a qualifying terminal assistant message's text as one final response only after work settles; it does not infer an internal commentary/answer boundary from prose. Cancellation removes automatic work-history collapse eligibility. Manual fold choices remain memory-only.

- **Layout.** Maintain a logical tree of leaves, disclosures, and bounded bodies. Native `ScrollView` instances provide logical offsets and bounds. Before a frame, allocate the original dock, measure dirty content at the final width, and intersect every logical clip. Paint each resulting contiguous leaf interval through one fully visible, non-nested native `ScrollView` containing the original uncropped rows. Exact interval heights, hidden painting scrollbars, and one presentation location per occurrence prevent a second native image crop. Keep the original image reservation rows and let Pi perform the sole crop, image transmission, placement, and terminal diffing. Preserve the first visible occurrence and local row when heights change, or follow the end when that viewport was already following.

- **Interaction.** Keep Pi's input decoding, effective keybindings, child pointer handlers, and clipboard transport. The extension maps normalized pointer coordinates to the original child's rows, offers events to that child first, and passes unused wheel movement from the innermost logical viewport outward. Native Page Up, Page Down, prompt navigation, and Find actions target the logical chat viewport, rather than one of its painting intervals. Selection endpoints identify occurrence, rendered row, and terminal cell. Copy traverses expanded content between the endpoints, including offscreen rows in an expanded body; collapsed content is excluded. Preserve native `app.message.copy` and copy-on-select behavior. Ordinary scrolling preserves selection. Folding, reflow, or changed selected content clears it without postponing the automatic transitions already agreed. Native overlays and composer focus retain priority.

- **Keyboard disclosure access.** One shortcut registered through Pi transfers focus from the composer to the nearest visible disclosure. Reuse Pi's configured selector up/down actions to move between disclosures, confirm to toggle, and cancel to return focus to the current composer. Use Pi's programmatic focus, configured key matching, focused-component dispatch, and overlay focus restoration; native overlays retain priority. This accepted focus interaction operates on the existing chat view and introduces no slash command or separate reader.

- **Search.** Search readable source fields independently of folds, retaining references and match ranges rather than a joined corpus. Reuse Pi's search input component with a source-search controller. Selecting a hit opens its enclosing folds, materializes missing historical rows at their source-ordered position without changing Pi's session projection, and reveals the occurrence through the logical viewports. Highlight the matching text when its rendered range can be established reliably. When a tool renderer omits or ambiguously transforms that text, highlight the owning call instead, preserving its presentation. No temporary excerpt or separate search preview is added.

- **Historical uncertainty.** Private observation can establish future delivery relationships but cannot recover provenance never stored. Leave only uncertain work relationships unfolded, retaining native order and available tool/thought disclosures and search. Do not invent work boundaries, phase metadata, or explanatory chat messages.

- **Invalidation and cleanup.** The owned root forwards invalidation to the saved native root exactly once, then invalidates its own geometry and owned presenters. Frame-local render references avoid rendering a borrowed component twice for measurement and painting. Rebind the painting and input adapters when Pi replaces its renderer during a mode switch. Mark adapter callbacks inactive, dispose owned selection/search timers and subscriptions, restore only the instance methods and root still owned by this adapter, and release references; do not dispose borrowed native components. Callbacks or wrappers retained by another owner must remain inert after disposal. Unsupported versions, structural mismatches, or competing chat-root ownership prevent activation rather than silently using incomplete presentation.
