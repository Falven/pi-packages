# Target native fullscreen chat interaction

The complete disclosure interaction targets Pi's fullscreen mode with keyboard access to every disclosure and supplementary mouse interaction, preserving [Pi's ownership of input and terminal behavior](0001-preserve-pi-extension-contracts.md) and ordinary terminal scrolling without rewriting terminal-owned scrollback. Pi's global tool-expansion action (`app.tools.expand`, Ctrl+O by default) expands or collapses every available disclosure together: enclosing agent activity (“Worked for…”), render groups, activity items, and native output expansion. Use the configured binding and Pi's global expansion state. New render groups, activity items, and their native output controls inherit that state.

Individual disclosures remain independently operable. Opening an activity item reveals its native output control, collapsed to Pi's preview by default. Native output clicks toggle only that control. Toggling an item, group, or enclosing agent activity alone preserves its descendants' disclosure choices. Those choices survive redraws, growth, settings reconstruction, and resizing until another explicit toggle changes them; the next global toggle applies its state to all disclosures. Choices remain in memory and reset on application restart or extension reload. The global action is an explicit disclosure choice under the [agent activity collapse policy](0015-final-response-outside-agent-activity.md); it does not hide the final response or change Hide thinking.

## Consequences

The [owned chat view](0022-native-rows-in-an-owned-transcript.md) manages selection in occurrence and rendered-row coordinates across its logical viewports, while reusing Pi's input decoding, effective keybindings, clipboard transport, and overlay focus restoration. One shortcut registered through Pi transfers focus from the composer to the nearest visible disclosure; configured selector up/down actions move between disclosures, confirm toggles the focused disclosure, and cancel returns focus to the current composer. Native overlays retain their focus priority, and the shortcut does not open another view or require a slash command.

Installed Pi 1.0.2 and source checkout 1.1.0 provide programmatic focus but no keyboard traversal from the composer to individual chat controls: Tab handles completion, Shift+Tab cycles thinking level, and viewport actions scroll without moving focus. The accepted focus shortcut supplies that missing entry interaction while retaining Pi's existing focus and keyboard mechanisms.

The approved copy delta extends this same focus path to enabled command, edit, and settled final-response actions. Selector confirmation activates the focused action, cancellation returns to the composer, and collapse removes hidden actions from navigation with sensible focus recovery. Copy clicks consume their own activation before disclosure or selection handling. No additional shortcut or setting is introduced.
