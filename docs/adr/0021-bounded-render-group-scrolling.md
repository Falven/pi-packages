# Let render groups and native output expand in conversation flow

An expanded render group exposes every activity item in ordinary conversation flow. Each item keeps its [independent item disclosure and native output control](0019-tool-renderers-own-tool-presentation.md). Use Pi's native output sizing without a shared group viewport, a separate body height cap, or a chat-specific percentage or row limit. This supersedes the bounded render-group viewport decision.

Source inspection of Pi 1.0.2 and 1.1.0 found that standard tool cells have renderer-specific collapsed previews, while expanded output grows with retained content in the conversation. Those preview limits are not scroll-area sizes, and standard expanded tool cells have no independent scroll viewport. Native sizing therefore takes precedence over the earlier request for separately bounded activity bodies. Collapsed activity items remain summary-only. Opening one reveals its native output control in its current state, showing Pi’s collapsed preview by default; clicking the native control expands or collapses only its output. Native preview limits apply inside the open item and do not create another scroll viewport. [Pi's global expansion action](0014-fullscreen-transcript-interaction.md) expands or collapses all available disclosures together.

## Consequences

Long expanded output can occupy many conversation rows; the primary chat viewport scrolls through it. Pi's existing output padding supplies conversation gutters under [ADR 0022](0022-native-rows-in-an-owned-transcript.md), providing direct conversation scrolling without extra width or a new setting. Where native content within an activity body supplies its own scrolling, preserve that behavior and pass unused wheel movement to the conversation at either edge. Do not create an inner viewport to simulate a native control that does not exist. Page Up and Page Down remain assigned to the primary chat viewport.

Keep native content renderers, image ownership, source occurrence geometry, selection, and scroll anchoring through the owned chat-view adapter. Native painting windows clip visible content; they do not impose another user-scrollable group or body. Scrolling requests a redraw without invalidating unchanged content or scanning history; additional caches require reliable invalidation and measured need.
