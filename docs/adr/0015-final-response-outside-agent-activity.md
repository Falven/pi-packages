# Keep the final response outside collapsed agent activity

The final response remains visible outside the agent activity disclosure, including when its text exactly matches earlier progress. `pi-chat` therefore requires occurrence-specific visibility at content-block granularity within Pi's [native-content boundary](0012-transcript-preserves-native-content.md); ambiguous text matching cannot substitute for that behavior by hiding the final response or exposing collapsed agent activity. Agent activity becomes eligible to collapse automatically as a qualifying final response starts, subject to explicit disclosure choices; cancellation or the absence of such a response prevents automatic collapse, while completion, text selection, and scroll position do not postpone it. An explicit individual or [global toggle](0014-fullscreen-transcript-interaction.md) can expand or collapse an available agent activity disclosure independently of that automatic eligibility.

## Consequences

Closing agent activity hides the agent's activity while keeping every user message visible, including steering messages delivered during that agent activity. These messages keep their native rendering and source order; opening the disclosure restores the agent's activity around them without duplicating or moving the user occurrences. Keep one neutral blank line between the last retained user-message bar and the final response, preserving native spacing when already present. Steering retains its existing agent activity relationship, and a delivered follow-up still starts separate agent activity.

Pi can put several provider message items into one assistant message, so acquiring its whole native component does not establish separate commentary and final-response visibility. The public [`provider_stream_event` hook](/Users/fran/Source/pi-packages/node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/types.d.ts:690) can expose an early OpenAI Responses `final_answer` phase before normalized text starts when the provider supplies it; the [runtime adapter](0022-native-rows-in-an-owned-transcript.md) associates normalized content occurrences with native child components. Provider phase, selected final response, and settled agent activity outcome remain distinct facts.

When the provider supplies no final-phase evidence, a qualifying terminal assistant message's text becomes one final response only after agent activity settles. This accepted Pi policy does not infer an internal commentary/answer boundary from prose or claim early collapse without provider evidence; cancellation and missing qualifying responses prevent automatic collapse under the policy above without overriding explicit disclosure choices.

Once the turn settles with a recognized final response, one Copy response action follows the entire answer outside agent activity, left aligned with its native content. Bind copying to the answer's stable source occurrence and selected final text parts, preserving their original Markdown in source order with Pi's text-part joining convention. Newer answers cannot change an older action's payload. This action reuses existing final recognition; it neither infers a final from prose nor invokes the global last-response copy handler. The control remains outside conversation, search, and selected text.

The agent activity header reads `Worked for 34m 49s ▶`, with whole elapsed minutes and seconds and a trailing `▶` when collapsed or `▼` when expanded. These larger glyphs use the normal terminal font size and line height. Use Pi's delivered-request entry timestamp through the last committed agent activity entry at settlement; before settlement, measure through the current redraw. This excludes queue waiting and preserves the duration after reload without adding stored timing metadata. Render a muted summary and a native thin divider with blank lines above and below the header. Use a text underline for focus, with no header background, so it cannot merge visually with the preceding user-message bar.
