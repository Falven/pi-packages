# Keep the final response outside collapsed agent activity

The final response remains visible outside the agent activity disclosure, including when its text exactly matches earlier progress. `pi-chat` therefore requires occurrence-specific visibility at content-block granularity within Pi's [native-content boundary](0012-transcript-preserves-native-content.md); ambiguous text matching cannot substitute for that behavior by hiding the final response or exposing collapsed agent activity. Enclosing collapse is available only when a qualifying final response has started, the turn is uncancelled, and there is renderable collapsible activity. Eligibility constrains both automatic and explicit collapse: cancellation or revoked final qualification reveals activity and removes the enclosing disclosure, even after a manual or [global closure](0014-fullscreen-transcript-interaction.md).

While eligible, an explicit enclosing preference takes precedence over the automatic default. Explicit child inspection prevents that default collapse but does not prevent a later enclosing closure. Find records an explicit open choice, including when the activity is temporarily ineligible. Scrolling, text selection, and header focus do not create inspection holds. Retain the same activity's memory-only preference through temporary ineligibility and apply it when eligibility returns; preserve descendant choices independently. Reference forced expansion belongs to other view/workflow modes and is not Pi's global toggle or inspection hold.

This replaces the independent-manual-closure policy previously recorded here and implemented by Chat 07 at `9f57ab9`. A stored preference cannot justify hiding a turn whose answer has been revoked or whose processing was cancelled. ## Consequences

Closing agent activity hides the agent's activity while keeping every user message visible, including steering messages delivered during that agent activity. These messages keep their native rendering and source order; opening the disclosure restores the agent's activity around them without duplicating or moving the user occurrences. Keep one neutral blank line between the last retained user-message bar and the final response, preserving native spacing when already present. Steering retains its existing agent activity relationship, and a delivered follow-up still starts separate agent activity.

Pi can put several provider message items into one assistant message, so acquiring its whole native component does not establish separate commentary and final-response visibility. The public [`provider_stream_event` hook](/Users/fran/Source/pi-packages/node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/types.d.ts:690) can expose an early OpenAI Responses `final_answer` phase before normalized text starts when the provider supplies it; the [runtime adapter](0022-native-rows-in-an-owned-transcript.md) associates normalized content occurrences with native child components. Provider phase, selected final response, settled outcome, enclosing eligibility, and explicit preference remain distinct facts.

For Pi's supported text path, an exactly associated `final_answer` item qualifies when its text is nonblank or its observed provider status is `completed`. A done event alone does not prove completion, and an unfinished blank replacement revokes qualification. A qualifying completed blank final can permit collapse without fabricated answer text or a blank answer row; native error and interruption notices remain visible. Preserve its exact source boundary rather than composing across an unidentified row or uncertain historical relationship. The reference also accepts structured output and excludes asynchronous delivery/user-input messages; Pi exposes no corresponding app-level message forms, so this change does not invent them. Ordinary JSON text follows the text path.

When the provider supplies no final-phase evidence, a qualifying terminal assistant message's text becomes one final response only after agent activity settles. This accepted Pi policy does not infer an internal commentary/answer boundary from prose or claim early collapse without provider evidence. A valid explicit partial final can remain eligible after a non-cancellation error; failure alone is not a blanket reason to expand. Actual cancellation prevents enclosing collapse, including when recorded at settlement after agent-end and on replay. Calling abort after successful settlement does not retroactively cancel that turn without a new host cancellation fact.

If the focused enclosing header disappears, return focus to the composer through the existing focus lifecycle. Keep the established relationship records and memory-only preference lifetime. Settled final references can restore a completed blank selection; phase-only history without enough qualification evidence remains visible.
