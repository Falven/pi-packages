# Attachments specification

**Status:** implemented

## Problem Statement

Users need pasted text, files, and images to enter a draft predictably and remain available after a source changes or a session resumes. They need small text inline, large text readable on demand, image previews, explicit attachment actions, and recovery when capture or submission fails. Clipboard metadata and terminal text paste can carry different content for the same physical gesture.

Attachment handling currently ignores some Pi image and editor preferences, and fixed attachment shortcuts can conflict with configured native actions. Separate file and text commands expose input sources as primary actions. Attachment membership is recognized only through a special link form under retained storage, so ordinary local-file Markdown does not yet provide a consistent way to add, remove, and restore attachments through editing.

## Solution

`pi-attachments` provides paste policy, attachment capture, previews, Restore Inline, draft membership changes, retained storage, and native submission delivery in one package. Native clipboard files and images become snapshots. A text paste that resolves to one readable regular file also becomes a snapshot; other text below 5,000 UTF-16 code units stays inline, and larger text becomes a readable attachment. Attach… offers File path… by default and Create from text… as a secondary source, with content type detected automatically. Valid local-file Markdown references also capture their contents when added, then point to the retained snapshot; removing the markup leaves ordinary path text.

The package honors Pi's effective image and editor settings. Pi owns configuration for Attach… and Manage attachments… bindings, and its standard settings menu offers Small, Medium, and Large thumbnail sizes. The current thumbnail bounds remain the default. These menu integrations require public upstream support; local settings fixes can ship independently. The package works with Pi's native editor and `pi-composer`; the supported environment is Ghostty on local macOS in Pi's fullscreen mode.

## Implementation Decisions

- The package owns paste policy, attachment capture, recovery, stored contents, metadata, preview, restoration, retention, and delivery. Its paste module classifies clipboard content and text; a shared internal capture operation prepares snapshots for both pastes and explicit actions; attachment UI and delivery consume those snapshots. Membership follows ordinary Markdown attachment references in the active editor's text. Editing or undoing those references changes membership through the editor's existing text history while storage remains attachment-owned.
- Snapshot text, files, and images when the attachment is added. A reference becomes usable only after its contents are successfully preserved. A newly valid Markdown reference to an uncaptured local regular file triggers capture and changes its destination to the retained snapshot before the first preview. Later previews, redraws, and normal, steering, or follow-up submission reuse that snapshot; later changes or removal of the original source do not alter it. Capture is independent of image visibility. Rendering, resizing, and settings changes never initiate capture.
- Membership follows normal Markdown semantics for inline links, reference-style links, local file autolinks, and image syntax pointing to local regular files. Code, escaped examples, unused definitions, and remote URLs do not establish membership. Existing retained targets are reused without another capture. Plain source paths remain references to current source files; stripping attachment markup leaves its destination as ordinary path text, which may identify a retained snapshot.
- Automatic destination replacement uses the active editor's mutation and history contracts. Preserve labels, surrounding text, caret, selection, focus, and unrelated edits while capture completes. Verify editing and undo behavior before implementing the combined flow; no renderer owns draft changes or snapshots.
- Use Pi's clipboard and image conversion/resizing helpers and standard Node filesystem facilities. Keep retained contents in stable package-owned storage using Pi's state-location conventions. Image previews and delivery conversions must preserve the original snapshot.
- Retain format extensions supplied by clipboard capture. Generated recovery filenames for supported native images include their image-type extension, so opening their references uses the system's associated image application. Preserve captured bytes, copied-file names, and existing snapshot paths.
- Link successfully loaded image thumbnail cells and filename fallbacks to their retained full-resolution file with Pi's native hyperlink helper and effective capability detection. Keep Pi's native Image component responsible for graphics. Use encoded local file URLs with an explicit localhost authority; native Pi or terminal activation opens the system's associated application without a package-specific launcher or terminal configuration change.
- Publish a clickable preview only after the retained file passes the existing storage and image checks. Links belong only to rendered output, cover the preview's reserved cells, and end before surrounding UI. Resizing, refresh, removal, and session changes update the clickable regions alongside visible membership. Opening does not edit the draft or transform the retained file; an external application's subsequent save follows ordinary file semantics and can change that file.
- Attachment-producing pastes call the shared capture operation directly with captured text, image bytes, or copied-file identities. The operation completes snapshot storage and recovery preparation before inserting references into the requesting draft. Attach… uses the same capture operation, storage, and lifetime rules. Paste preparation does not create a second persisted copy, temporary source links, or a command submission.
- Attach… opens a native source chooser with File path… selected by default and Create from text… secondary. File path… accepts the established absolute, relative, home-relative, local file-URL, quoted, and shell-escaped path forms without shell evaluation; Markdown destinations use Markdown escaping and the requesting draft's working directory. Determine file content type automatically. Create from text… captures the entered text literally, including path-looking strings and empty text, without trimming its final newline. Cancelling either source dialog closes the whole flow, discards unfinished entry, and leaves the draft unchanged.
- Show a compact Manage attachments shortcut hint and small image previews near the active editor through Pi's `setWidget` facility. Attachment names remain in the draft references and management picker; the widget has no duplicate count or filename heading. Render previews with Pi's `Image` component and graphics capabilities, and use native overlays for attachment actions and text preview. Loading, refresh, resize, invalidation, and preview errors preserve the editor's text, selection anchor/range, history, and focus.
- The configurable actions are Attach… and Manage attachments…, with Ctrl+Alt+F and Ctrl+Alt+A as their respective defaults; Pi displays Alt as Option on macOS. Pi owns named actions, user bindings, conflict handling, and standard-menu configuration through public upstream support. The extension has no separate keybinding configuration. The widget uses the effective management binding. `/attach` opens the chooser and `/attachments` opens management through native leading slash-command dispatch; appending a command to draft text does not invoke it, and inline slash completion retains its skill-reference behavior.
- Focused attachment-management and preview components own their navigation, acceptance, and cancellation through native routing. Cancelling or closing a preview returns to the unchanged draft and selection. An accepted action changes the draft only through the active editor's public text interfaces; its key cannot also trigger background editing or submission.
- Clipboard attachments arrive through the effective native clipboard handler and paste policy. A clipboard manager's native file item and a recognized single-path text paste use the same snapshot, image-preview, and delivery behavior as any other copied file. Terminal text supplies no clipboard metadata; its complete payload determines which file to capture. Verify native clipboard and terminal text delivery independently of the physical shortcut used.
- Management remains file-level, with one item per unique retained file path. Preview text opens that file's retained text in a read-only, scrollable native dialog; it does not insert contents, edit the file, or change membership. Preview text and Restore Inline remain management options without separate configurable shortcuts.
- Restore Inline inserts the complete preserved text once at the current caret or replaces the selection, then removes all corresponding attachment references for the selected retained file. The reference was already in the draft; restoration converts its separately stored contents into ordinary editable text. The native editor retains its tab expansion to four spaces and LF normalization; `pi-composer` preserves tabs, and the snapshot bytes remain unchanged. Restoration is an explicit inline action even when the text exceeds the paste cutoff.
- With `pi-composer`, restoration, removal, or attachment insertion and its related text changes form one undoable action. Undo/redo must restore membership without losing the required stored contents.
- Remove from draft removes all attachment references for the selected retained file and therefore its membership in that draft. Preserve stored contents needed by another saved draft, in-memory undo, or a retained submission. A preview failure must not imply that the stored attachment has been removed.
- Removing an attachment reference's Markdown while keeping its destination leaves the saved snapshot path as ordinary text. The incomplete or removed reference no longer contributes membership, preview, or submitted image content. Ordinary edits do not capture that path again; the retained snapshot remains readable.
- An incomplete attachment reference cannot absorb a later reference or unrelated prose. Removal and Restore Inline operate only on the selected attachment's complete reference ranges; recognition remains linear for repeated incomplete markers.
- Text preview wraps bounded chunks for its current viewport with Pi's native text component. Exceptionally long logical lines may gain a visual wrap between chunks; stored contents remain unchanged. Paging and resizing retain access to the complete text, including Unicode and tabs, without materializing every rendered row at once.
- Associate saved attachment references with native session identity. Restore readable references with session drafts and preserve the contents needed by resumed sessions and forks. Retained snapshots and recovery records persist even with --no-session; session-file persistence does not control attachment retention.
- Retain every snapshot that has entered a draft, including contents reachable through hidden editor history, saved sessions, submissions, or forks. Explicit cleanup reclaims only proven-unused capture or staging data; pending writes, recoverable contents, and data with uncertain eligibility remain retained. Pi's public contracts cannot enumerate every live undo history or session-file location. Retained storage remains usable across application restarts.
- Text and file attachments contribute readable snapshot references to the submitted prompt; their full bodies remain available on demand. Images use native image content. Existing images and other input transformations must survive composition with attachment delivery.
- Read Pi's effective settings through public services, preserving Pi's defaults and overrides instead of reading configuration files independently. Use the effective values for each affected operation so changes made through Pi apply without recapturing contents. Honor `images.autoResize` when preparing attachment images, retain required image-format conversion, and preserve captured originals. Honor `terminal.showImages` for attachment graphics and `editorPaddingX` in the separate text-entry dialog. Image visibility affects graphics, not capture, membership, or eligibility for image delivery.
- Pi's standard `/settings` exposes one Attachment thumbnail size choice: Small (12 columns by two rows), Medium (24 columns by four rows, the default), and Large (48 columns by eight rows). These are bounding boxes; preserve aspect ratio, with Pi's `terminal.imageWidthCells` preference and available terminal space as ceilings. Increasing Pi's general image width does not enlarge thumbnails beyond the selected bounds. Thumbnail sizing does not change retained bytes or delivered image dimensions. This preference requires additional public upstream settings support. Until that integration is available, retain the current Medium bounds; visibility, resize, width, and padding fixes can ship independently.
- Deferred image preparation follows the effective delivery-time policy, including `images.blockImages` and changes while a message is queued. Do not bypass preparation based on the capture-time or enqueue-time value: an image blocked then may be allowed at delivery. When images are blocked at delivery, skip attachment image preparation and let Pi enforce its final image policy. When allowed, prepare the retained image using the effective resize preference and required format conversion. A preparation failure rejects the affected submission without cancelling unrelated active or queued work, silently omitting an image, or losing retained history and recovery. This requires a public Pi delivery boundary that can reject one submission and continue unrelated work; it is a separate milestone from local settings fixes. Preserve other handlers' images through composition and normal, steering, and follow-up delivery; Pi remains the final authority over delivered images.
- Preserve native submission, command dispatch, and steer/follow-up behavior. Deliver the attachments associated with the submitted draft, including requests whose supporting material is entirely attached. Draft clearing is not evidence that delivery succeeded.
- Automatic text attachment capture preserves exact bytes through the same retry-save action as copied files and images. Explicit text-dialog save failures retain the editable dialog contents. Unsupported clipboard image bytes remain durably recoverable with an error and no insertion.
- Bind asynchronous reads, writes, previews, and delivery preparation to the requesting draft and attachment. Preserve later unrelated edits and report failures with enough context for recovery.
- Cooperate with editors and other extensions through existing public Pi contracts, including native text insertion, widgets, input transformations, and lifecycle/state facilities. Direct capture stays internal to this package. Combined undo follows ordinary Markdown attachment references and the active editor's text history; native text callbacks do not acknowledge model submission.
- Use native clipboard facilities for plain text, Markdown, copied file paths, and images. The native clipboard route preserves Pi's content precedence: native copied-file information before image data, then plain text. A clipboard read error remains an error rather than being treated as a different content type.
- Before measuring text length, interpret the entire decoded text paste as one file path. Support absolute paths, bare names and relative paths resolved against the requesting working directory, home-relative paths, local file URLs, whole-path quotes, and the escaped path spelling produced by terminal paste. Preserve spaces within a filename. Do not split space- or newline-delimited path lists, evaluate shell expressions, or inspect the caret's Markdown context.
- Capture a readable regular file through the shared snapshot operation. An unsuccessful path match, including a missing or unreadable file or a directory, silently follows the ordinary text policy with the original payload. Once file contents are captured, storage failures retain the existing error and recovery behavior.
- Measure other decoded text pastes in JavaScript UTF-16 code units before editor formatting. A text paste shorter than 5,000 units is inline; a paste of at least 5,000 units uses text-attachment handling. The policy has no line-count or accumulated-draft-length condition.
- Assemble a bracketed paste as one action even when terminal input arrives in chunks. Classify the complete payload once. The native editor retains its tab expansion to four spaces and LF normalization; `pi-composer` preserves tabs. Attachment snapshots preserve the captured contents independently of editor whitespace handling.
- Apply the policy to terminal paste, clipboard shortcuts, right-click paste, and native `pasteToEditor` calls at every caret position, including code and link destinations. Terminal bracketed paste and `pasteToEditor` supply text; process that payload without rereading the clipboard. Native clipboard actions supply the separate metadata-aware route. Ordinary typing, native text replacement, and restored drafts invoke neither bare-path recognition nor the cutoff; valid local-file Markdown references follow the attachment capture lifecycle separately.
- Keep reference insertion at the active caret or selection. The resulting Markdown determines membership independently of paste classification: a generated reference inside code remains literal text, with its snapshot retained for later use. Making it a valid link outside code establishes membership without another capture.
- Create from text… explicitly captures supplied text regardless of whether it names a file or exceeds the cutoff. Restore Inline is the existing route from a captured text file to editable draft contents. Attachment membership remains editable through Markdown; there is no separate Paste Inline action or command.
- File and image outcomes use attachment handling. Preserve native clipboard file identities and path validation. Native copied-file metadata may identify a set of files; the text-paste route attempts only one whole path. Path spelling is resolved without shell execution or a new clipboard read, and the captured file retains its name and bytes through existing storage rules.
- Resolve native clipboard input through the supplied manager's effective `app.clipboard.pasteImage` action, whose macOS default is Ctrl+V. Use its public user-binding information: any explicit override, including an empty list or a repeated default, suppresses the package's raw Cmd+V convenience alias. This applies with the native editor as well as `pi-composer`; neither package can restore an alias the configuration suppressed.
- For clipboard-manager files and images in Ghostty, copy the selected item to the system clipboard, return focus to Pi, and invoke its effective native clipboard action. With PastePal, use the selected clip's Copy action, then Ctrl+V under Pi's default macOS bindings. Use Pi's native shortcut information when the action is remapped. This workflow requires `pi-attachments` and works with either editor; the clipboard manager's one-step Paste action is a separate input route.
- Supply a clipboard handler only when one is absent. Earlier handlers and later assignments retain their chosen insertion behavior, including direct insertion; a deliberate direct insertion is distinct from the public paste route governed by this policy.
- Preserve native input dispatch and existing listeners that transform or consume input. Native actions, accepted extension shortcuts, and focused components keep their input before a raw Cmd+V fallback. A handled key must not also read the clipboard or edit the draft. Raw listeners, direct editor paste, and native clipboard insertion are different host routes; demonstrate each required route without adding a separate keybinding manager or configuration reader.
- A physical Cmd+V, terminal menu action, or right-click may produce bracketed text rather than a raw key or native clipboard action. Disabling the raw alias does not disable a delivered text paste. Classify the decoded text actually supplied, and report the observed route when verifying behavior. Keep terminal settings unchanged.
- Preserve Ghostty's Cmd+V binding and its ordinary paste behavior outside Pi. Terminal setup keeps the existing eight forwarding rules. A terminal-converted single file path enters snapshot capture when readable; image-only clipboard contents remain available through Pi's native clipboard action.
- Keep existing attachment snapshot paths, Markdown references, session records, and durable recovery files readable. Preserve earlier `pi-paste` recovery data in place, including captured bytes and requesting-draft metadata; recovered files remain attachable through the native file action. Pending in-memory capture recovery remains available across extension reloads and session changes.
- Retire `paste-inline`, `attach-file`, and `attach-text` without compatibility aliases, and retire the Ctrl+Alt+V and Ctrl+Alt+T shortcuts. No supported production integration requiring those commands has been identified. Preserve `paste-recover`, `attachments-recover`, and `attachments-cleanup`; `paste-recover` aliases the shared attachment recovery action. Recovery retries retained content without inserting it into a newer draft. If Pi exits before a failed write can be retried, contents held only in memory are lost.

## Testing Decisions

- Test through the existing public Pi editor/session boundary using loaded extensions and temporary attachment storage. Control provider, terminal, clipboard, and OS-launch boundaries while exercising real editor and session behavior. Assert visible membership, previewed/restored text, preserved bytes, submitted references/images, and readable files after lifecycle changes. Avoid assertions about private metadata layout or storage helper calls; upstream integrations use this same public boundary as it becomes available.
- Exercise explicit actions and every paste route with `pi-attachments` and native Pi, then with `pi-composer` for shared history. Use the same host setup to verify compatibility with native input transformations, existing clipboard handlers, editor decorators, and UI registrations.
- Use the existing Node test runner. Pi's clipboard/image tests, virtual-terminal tests, and extension input-event tests provide prior art for content fixtures, native rendering, and transformation chaining. Reuse the package's public-host fixtures and behavior tests.
- Cover the following observable scenarios:

## Out of Scope

Draft text, selection, editing bindings, and undo history belong to the active editor. Inline skill completion and expansion belong to the skill-reference package.

Support for the configured external editor inside Create from text… is a later milestone. It must preserve exact accepted text, including the final newline, rather than adopting a helper that removes it.

## Further Notes

Work is integrated on `main` in both the consumer and upstream repositories. The upstream work starts from `3daa20280f6a7c7cbe0935680c9a38fdc3863005`. Its package version is 1.2.0, but that version number does not identify a published build containing these changes. The new public interfaces remain unreleased. A clean installation using the consumer's pinned Pi 1.0.2 dependencies cannot run the complete integration; update the dependency floor only after an upstream release containing the required interfaces exists.

Pi owns named extension actions, effective bindings, and enum settings in its standard menu. Its public targeted-edit and text-identity contracts preserve the requesting editor state through asynchronous capture, undo, prompt history, and collapsed native pastes. A submission-preparation boundary receives the actual editor identity and awaits existing captures before ordinary input transformations. It does not infer a draft from matching text or create a snapshot on Send. Editor submissions preserve receipt order through preparation without waiting for provider responses; queued message identity remains intact for other extensions. A separate delivery boundary prepares images using current policy and can reject one submission while unrelated work continues. Local image-visibility, resize, width, and padding fixes remain independently usable.

Markdown destinations decode named and numeric character references while preserving escaped ampersands, local file autolinks, and literal `%20` in ordinary paths. Generated destinations escape Markdown syntax. Historical `Attachment:` references, including renamed labels and image syntax, reuse an existing literal retained filename before normalizing the destination. That compatibility lookup occurs when the reference enters the draft; previews wait for it and redraws reuse its result.

Build and install one coherent set of public packages from the upstream `main` branch containing this work for local verification. The existing packaging tools keep direct and transitive Pi dependencies together. After hydrating the checkouts' locked dependencies, use:
