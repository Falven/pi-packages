# pi-chat specification

## Problem Statement

Pi users need to follow current activity, inspect earlier agent activity, and find retained conversation content without reading an unbroken stream of commands, thoughts, and output. Existing extensions provide parts of this experience, but their overlapping rendering and input changes can conflict.

The chat view groups consecutive activity and collapses earlier agent activity while keeping the final response visible. Pi's native Hide thinking choice controls whether thoughts appear inline. It must operate inside Pi's terminal interface, preserve the original conversation, and reuse native content presentation. It must not require a separate application, service, Pi fork, or modifications to Pi's installed source.

The current agent activity composition can stop at an unrelated extension notice before reaching the known final response, leaving surrounding agent activity expanded. Custom entries inserted during streaming can also miss source association. Execution status needs to stay inside its native tool presentation, while unrelated notices need to remain visible without preventing known agent activity from collapsing.

## Solution

Build `pi-chat`, one extension that owns the main chat view in Pi's fullscreen mode. A chat view is the primary conversation surface alongside the composer; a transcript is a separate history-reading overlay and is outside this package's scope.

The extension composes Pi's existing message and tool components into occurrence-aware agent activities, render-group disclosures, and native thought Markdown in ordinary chat flow. Final responses appear after their agent activity and remain visible when that history closes. Expanded render groups use bounded viewports; visible thoughts have no separate header, viewport, or disclosure. Hide thinking removes thought rows completely while retaining their source and native working labels. Source Find temporarily reveals only its selected hidden thought occurrence without changing Hide thinking.

Correct native custom-entry binding and agent activity composition so unrelated notices remain visible in their original order while surrounding known agent activity disclosures. Execution status collapses with the native tool component that owns it. For `pi-codex-tools`, this targets its separately specified native `exec` presentation; this correction does not implement that package's renderer or adapt its earlier standalone execution journals.

Pi continues to own conversation data, execution, effective Markdown and tool rendering, the composer and surrounding dock, themes, terminal protocols, and final painting. One isolated adapter supplies the private runtime access required for exact native component identity and composition. Pi 1.1.0 and later are the primary target. Compatibility depends on required capabilities rather than a version string; real-host tests also retain coverage for Pi 1.0.2. Regular mode and the history printed on exit retain native behavior.

## Implementation Decisions

- **Package and ownership.** Implement `pi-chat` as one extension with internal modules for the host adapter, occurrence and relationship indexing, disclosure policy, layout and interaction, and source search. These modules share one lifecycle and source identity model. Do not publish a support framework or require the composer, attachments, or skill-reference packages as runtime dependencies.

- **Native content boundary.** Pi remains the canonical owner of messages, session entries, model context, execution, and the native event reducer. Borrow its actual message and tool components and retain the effective renderer chain. Never insert markers into message content, replace messages for rendering identity, or maintain a second joined conversation buffer. Render-only source references and native rendered-line caches do not become conversation history.

- **Runtime compatibility.** Use one in-process adapter as the accepted exception to the repository's usual public-extension-only boundary. Check required functions when acquiring hooks and preserve native chat-root ownership. Missing hooks must produce an error naming the function; missing hooks or competing ownership prevent activation, restoring changes made during a failed attachment. Do not gate on Pi's version string. Target Pi 1.1.0 and later, validate against 1.1.0, and retain secondary coverage for 1.0.2; function presence alone does not prove behavioral compatibility with future releases. Prefer public APIs when available, including settlement cancellation and selection reset, retaining private fallbacks only where the tested runtimes require them.

- **Host acquisition and root replacement.** Capture the actual `InteractiveMode` through a scoped observation of the native widget method reached by `ctx.ui.setWidget`; restore the prototype descriptor immediately. Verify TUI mode and the same session manager. Save and replace `fullscreenLayoutRoot`, reusing the exact pending-message, status, widget, editor, and footer containers. Leave the native document, chat container, and event reducer alive. Use the original document in regular mode and for history printed on exit.

- **Reload bootstrap.** Native history can be constructed before `session_start` on reload or session replacement. During extension initialization, temporarily observe `renderSessionEntries`. Recognize the owning runner by the function identity of the extension's registered relationship-entry renderer, install the instance adapter before history construction, and restore the prototype. Disarm any remaining observer at `session_start`; use widget acquisition for initial TUI startup. Support the normal Pi CLI lifecycle. Abandoned extension discovery through custom SDK loaders is outside this lifecycle contract.

- **History assembly and binding.** Call native `renderSessionEntries` with a shallow array referencing original entries. Observe its entry-local `flatMap` projection on that array to associate actual projected items with their source entry and item ordinal, leaving entries and messages untouched. Pass the items to the original `renderSessionItems` through a scoped iterator so association remains available during native tool, notice, and message construction. Preserve native selection reset, projection rules, and options; restore the scoped method in `finally` and fail explicitly if association is lost. This retains a dependency on the native `flatMap`-then-`renderSessionItems` path. Observe insertion and removal paths. Associate each original native custom-entry component with its actual source entry whether Pi appends it or inserts it directly before a streaming assistant component. Cover live construction and replay through the same adapter; an append-only observer is insufficient. Source identity alone does not establish agent activity membership. Keep unpersisted native notices by component identity and insertion position. Do not trigger an extra destructive history rebuild.

- **Native component association.** Associate assistant content parts and adjacent thinking runs with the children produced by native construction, including its trimming and thinking aggregation. Rebind those references after native assistant updates recreate children. Preserve native semantic terminal markers. Borrow actual tool components with their renderer state, callbacks, and image instances; do not create another active presenter for the same call.

- **Native execution status.** Execution progress, results, and late status updates belong to the native tool presenter that owns them and follow that presenter's render group and agent activity disclosures. The tool renderer establishes their association with the initiating call, including updates after the final response or during a later request. `pi-chat` keeps borrowing and repainting that component at its established occurrence without duplicating it or resetting disclosure choices. For `pi-codex-tools`, target the native `exec` presentation in ADR 0024, whose routine execution journals are invisible as standalone chat rows. Do not parse `core-tools.activity`, reconstruct execution ownership, or add compatibility code for the earlier standalone journal presentation. This is a dependency on the separate tool-renderer revision, not a change to that package within this spec.

- **User-message layout.** In fullscreen chat, render the existing native `UserMessageComponent` at the full chat width, retaining its full-width themed background bar. Align its rendered content as one block to the right with native right padding while preserving relative Markdown indentation and layout. Use the native blank padding row to fill the bar background during cell-aware composition. Keep OSC 133 markers at the row prefix, translate child pointer coordinates, and let search and selection use the displayed aligned rows. Copying selected user text excludes only the added left layout margin and retains native content indentation. Preserve original message data, regular mode, and printed-exit rendering.

- **Native presentation settings.** Pi remains the source of settings, defaults, and allowed values. Read its current `outputPad` and native transcript scrollbar mode before layout; do not duplicate settings or introduce new flags. Use native components for render-group and agent-activity headers with the current padding, including the agent activity divider. Pi updates its live message and tool presenters; propagate padding changes through available native setters on detached historical presenters. Use native scrollbar style callbacks and `getContentWidth()` before measuring or aligning rows. Native `always` reserves its gutter, `auto` retains native overlay and hiding behavior, and `hidden` leaves it absent. Reuse native track clicks, thumb dragging, hover, timing, and painting. The older Pi 1.0.2 tool presenter has a fixed inset and its settings path can rebuild history; preserve those native behaviors rather than adding private compatibility code.

- **Absent historical content.** Materialize rows omitted by Pi's compaction-aware display projection through native factories into a detached destination, without populating editor history or clearing live pending-tool state. Use historical tool initialization without execution-start behavior or speculative edit previews. For otherwise-hidden thought bodies, use native assistant construction with a render-only array referencing the original thought blocks and the current Markdown environment. Reuse these owned historical presenters until a relevant invalidation or lifecycle change requires replacement.

- **Occurrence identity.** Assign a stable presentation handle to each source occurrence. A live handle points to the current live message and content part; after native persistence, promote that same handle to its committed entry and part reference. Use source entry and projected item ordinal where one entry yields several native items. Content equality, hashes, callback order, timestamps, and screen position do not determine occurrence identity. Equal progress and final text therefore remain independently addressable.

- **Incremental indexing.** Index the raw active branch once, including retained originals omitted by compaction. Reconcile appended entries and changed live occurrences incrementally, and rebase on session or branch changes. Retain references, classifications, revisions, and relationships rather than copied message bodies. Scrolling and collapsing consume the existing index; they do not scan history or hash unchanged content. No hashing dependency is required by this design.

- **Actual input delivery.** Observe the message objects passed to the particular agent's initial prompt operation and returned by its steering and follow-up queue drains. Preserve calls and return values unchanged. Certify delivery only when the corresponding user message starts. An agent listener ordered after native session persistence joins delivered objects to committed entries. Submission intent, queued text, or an input-handler snapshot cannot establish delivery, including when queued prompts contain identical text.

- **Agent activity relationships.** A delivered steering message continues the current agent activity and forms a user boundary between render groups. Every user message remains visible when agent activity is collapsed. Expanding agent activity restores agent activity around the same user occurrences in source order, without duplication. Derive final-response spacing from the last retained visible row, including an intervening notice, rather than an earlier user row. When that last row is a user-message bar, keep one neutral blank line before the final response; reuse native spacing rather than adding a second gap. A delivered follow-up starts a new turn with its own agent activity and answer relationship. An assistant message boundary or agent-loop boundary alone does not begin new agent activity.

- **Standalone extension notices.** A positively identified standalone extension notice without established agent activity membership remains visible while the surrounding known agent activity composes with its selected final response. Keep activity within the turn, retained user rows, and notices in one native-ordered sequence. Closing agent activity hides only its known activity within the turn; reopening it restores those activities around the same retained rows without duplication. Visible notices continue to split render groups. A notice alone does not create an empty agent activity disclosure. Preserve actual request, history, and compaction boundaries, stop at agent activity for a different known turn or an unidentified message row, and never move a notice after the selected final response ahead of it. Do not infer notice ownership from arrival time, the current request, or matching text. This treatment does not make every native status or unknown row transparent to agent activity composition.

- **Relationship persistence.** Append only minimal native custom session entries for certified delivery, agent activity, and final-phase relationships needed on replay. They contain classifications and source references, never copied conversation text or disclosure choices, and remain outside model context. Interpret references within the session journal so copied history in a fork can be rebased. Persist established facts, not guesses that attempt to repair missing provenance.

- **Historical uncertainty.** When historical delivery or phase provenance is unavailable, leave only the uncertain agent activity relationships expanded. Preserve known ordering, tool disclosures, inline thoughts, and search. Do not invent boundaries, phase labels, or explanatory chat messages. Missing historical provenance is distinct from an unsupported host structure, which prevents adapter activation.

- **Activity eligibility and summaries.** Every top-level tool call is eligible. Consecutive calls accumulate across assistant messages until visible commentary, visible thoughts, user rows, other standalone non-tool activity, or an explicit boundary intervenes. When Hide thinking is on, omitted thoughts do not separate eligible calls; visible commentary and meaningful boundaries still do. Eligibility does not depend on summary classification. One group-summary module caches normalized facts by call occurrence only when public `sourceInfo` identifies a built-in: `read`, `grep`, `find`, and `ls` give “Read files”; `edit` and `write` give “Edited a file/files” by distinct normalized source path; `bash` gives “Ran a command/commands” without parsing shell text. A skill-definition read recognized through public `getCommands` skill metadata gives “Loaded a tool/tools” by distinct path. Unknown or replacement calls, including historical calls without observed provenance, give “Called a tool/tools.” Weak references to Pi-owned entries and content indices share observed state through native settings row reconstruction within the same load, but do not persist provenance across new loads. Empty summaries say “Worked.” Do not scrape renderer titles, exclude tools, persist provenance, or require a tool-supplied grouping protocol.

- **Group summary lifecycle.** Combine supported collapsed segments in this fixed order: loaded tools, generic tools, edited files, read files, commands. Use sentence-initial case for the first segment, lowercase for later segments, and commas between segments. Counts choose “a file/tool/command” versus plural but are not printed. Public execution start/end events provide active group summaries: “Reading” a basename (or `/` for a root path) or skill, “Searching” files in a folder or for a nonblank query, “Listing” files, “Editing files,” “Running” nonblank command text, or generic “Calling a tool” when action facts are unavailable. Clear active status on cancellation and agent end; a missing result alone never proves a call is running. Ordinary scrolling reads cached summaries. Do not infer web, integration, visualization, or image actions without reliable Pi metadata. Expanded tool presentation and the separate thought working-message label retain their native owners.

- **Render group lifecycle.** Every consecutive render group keeps its outer disclosure, including a settled group with one finished call. Groups begin collapsed, including while executing. A group stays active while additional consecutive calls can still join; completion of its current call alone does not settle it. Preserve manual expansion through growth and completion. Ordinary call failure or cancellation does not change its disclosure choice. Each call keeps its native disclosures inside the group. One call editing many files remains one call.

- **Disclosure interaction and lifetime.** Pi's global tool-expansion action controls group and activity-body expansion. A group-only toggle preserves child activity-body disclosure choices; whole agent activity collapsing is independent. Store manual choices in memory, retaining them through redraw, growth, completion, and resize while their disclosure exists. Reset them on application restart or extension reload. Do not store choices in conversation content or relationship entries.

- **Final-response selection.** Keep provider phase, selected final response, and settled agent activity outcome as separate facts. Associate provider phase evidence with the exact normalized content occurrence, including when several provider items share one assistant message. Remove the selected final occurrence from the agent activity sequence and present it after the agent activity. Never identify it by matching text. Native user and standalone activity ordering remains intact.

- **Agent activity collapse.** Agent activity becomes eligible to collapse as qualifying final-response text starts, subject to explicit expansion and keep-open choices. A successful completion is not required. Selection and scroll position do not defer automatic collapse. Cancellation removes automatic collapse eligibility and leaves agent activity expanded even after a partial final response; render groups retain their independent state. No qualifying final response also leaves agent activity expanded. A terminal error that disqualifies the final candidate returns agent activity to that condition; failure alone is not a blanket completed-answer requirement.

- **Agent activity header.** Display `Worked for <minutes>m <seconds>s` followed by `▶` when collapsed or `▼` when expanded. Derive whole elapsed seconds from the delivered-request entry timestamp to the last committed agent activity entry at settlement; while unsettled, use the current redraw time. Do not count queue waiting or restart the duration on reload, and add no timing metadata or timer. Render the summary with the native muted color and a native thin divider below it, both using the current output padding. Leave a neutral blank line above the header and below the divider in both disclosure states. Focus underlines the summary only; the header and divider have no background.

- **Providers without final-phase evidence.** When the provider supplies no usable final-phase information, treat the text of a qualifying terminal assistant message as one final response only after agent activity settles. Do not split its prose into commentary and answer, infer phase from wording, or promise early collapse without evidence. Preserve cancellation and missing-final behavior.

- **Thinking visibility.** Reuse Pi's native `hideThinkingBlock` setting and its existing controls. When true, omit reasoning rows entirely, including placeholders, headers, spacing, and disclosures; group eligible tool calls across omitted thoughts. If reasoning was the only agent activity before a final response, also omit the otherwise-empty Worked disclosure. When false, preserve full inline native thought prose apart from extracted activity headings, and let visible thoughts separate render groups. Apply the same rule to retained and compacted historical reasoning. Preserve canonical source and searchability in either mode. Add no setting or raw-versus-summary distinction; provider and model controls remain Pi's responsibility.

- **Inline thoughts.** When Hide thinking is off, show native thought Markdown at each thought's source-ordered chat occurrence in ordinary flow, apart from extracted activity headings, reusing native renderers and caches. Keep it visible after completion whenever its enclosing agent activity is open. Give thoughts and adjacent render groups visual separation. Thoughts have no separate header, bounded viewport, or keyboard/mouse toggle; whole agent activity collapsing remains independent. Do not move them to a docked widget. Account for the native renderer's adjacent thinking-block aggregation in source mapping.

- **Activity headings.** Treat a standalone bold paragraph anywhere in thinking, including midway through a block, as a transient activity label in Pi's native working indicator in either Hide thinking mode. Use Pi's public `registerMarkdownTransformer` only for assistant-thinking display to omit that paragraph from the native thought body; inline bold emphasis remains ordinary prose. Public `message_update` sets the latest recognized label through `ctx.ui.setWorkingMessage`, and `thinking_end`, `message_end`, and `agent_end` clear this extension's label. Keep original thinking blocks in the native presenter and preserve canonical messages and session history. Add no occurrence-targeting hook, alternate renderer, custom spinner, package, or setting.

- **Logical viewports and anchors.** Maintain a logical tree of source occurrences, disclosures, and bounded bodies. Compose Pi's `ScrollView` state for offsets and bounds. Keep a render group's header outside its bounded scrolling body; expanded whole agent activity occupies normal chat flow. Preserve the first visible occurrence and local row when heights change, or follow the end if that viewport was already following.

- **Layout and native painting.** Allocate the existing dock first, then measure dirty content at its final content width and intersect all logical clips. Register the owned primary `ScrollView` in Pi's layout so native scrollbar geometry and input use the full logical chat height. Its child supplies blank geometry rows and positions the visible intervals between spacers above and below. Each interval remains a native `ScrollView` over original uncropped rows, with its exact visible height and its own scrollbar hidden. Keep these painting windows at terminal width inside a non-shrinking native `HStack`; the outer content clip excludes any reserved gutter while preserving Pi's full-width image recovery path. Give each occurrence one presentation location. Retain image reservation rows and native image instances. Only the leaf window supplies image content, so Pi performs one image crop, transmission, placement, and terminal diff despite the outer scroll layout.

- **Rendering cost.** Preserve native renderer instances and caches. Use frame-local references to rendered rows so measurement and painting do not render a borrowed component twice. The outer scroll geometry retains one blank string reference per logical display row, resizing only when the height changes; it stores no conversation text or joined rendered transcript. Scrolling changes offsets and requests a redraw without invalidating unchanged Markdown. Add another cache only when all invalidations can be observed and measurements justify it. Native opaque renderers can still traverse or render a whole body; a small viewport does not establish bounded rendering cost.

- **Pointer and navigation routing.** Use Pi's terminal input decoding and effective bindings. Map normalized pointer coordinates through logical geometry to the original child, offer events to that child first, and pass unused wheel movement from the innermost logical viewport outward. Native Page Up, Page Down, prompt navigation, and Find target the primary logical chat viewport rather than a painting interval. Preserve overlay priority and composer behavior.

- **Keyboard disclosure access.** Register one shortcut through Pi to transfer focus from the composer to the nearest visible group, agent activity, or tool disclosure. Reuse configured selector up/down actions to move between disclosures, confirm to toggle, and cancel to return to the current composer. Use `▶` for collapsed group and agent activity disclosures and `▼` for expanded ones, at the normal terminal font size and line height. Keep expansion chevrons visible without an extra arrow. Highlight focused render group headers with Pi's native selection background; agent activity headers have no background and underline only their focused summary. Inline thoughts do not enter disclosure navigation. Use native focus dispatch and overlay restoration. No slash command or separate reading view is introduced. The concrete shortcut chord was not selected during design; binding it must respect native action conflicts rather than silently repurpose completion or thinking controls.

- **Selection and copy.** Own selection geometry within the chat view using occurrence, rendered-row, and terminal-cell endpoints. Traverse expanded content between endpoints, including offscreen rows within expanded bodies, while excluding collapsed content. Reuse native `app.message.copy`, copy-on-select, and clipboard transport. Constrain selection highlighting to the content width so the reserved scrollbar gutter remains unselected; copy uses native content rows and excludes scrollbar glyphs. Preserve selection during ordinary scrolling; clear it when collapsing, reflow, or selected-content changes invalidate the range, including a scrollbar mode change that changes content width. Clearing selection does not delay agreed automatic disclosure transitions.

- **Search corpus.** Search retained readable source fields on the active branch and its ancestry, including messages, thoughts, commands, tool results, and pre-compaction originals. Extracted activity headings remain searchable in canonical thought source. Match Markdown link labels and code bodies, excluding structural markup and hidden destinations. Keep source-field references, revisions, and match ranges rather than a joined corpus. Sibling branches are excluded. Revalidate results after source changes or branch rebasing.

- **Search input and reveal.** Reuse Pi's search input with an owned source-result controller because native Find searches rendered lines. Selecting a hit opens its ancestor disclosures, creates any missing historical native row at its source-ordered position without changing Pi's session projection, and reveals it through the logical viewports. A hit on hidden thinking temporarily reveals only that selected occurrence using native thought Markdown. Navigation or a query change moves or removes the reveal; closing Find removes it. Hide thinking remains unchanged. This applies to retained and pre-compaction thoughts too. A hit on an extracted activity heading opens the containing agent activity and reveals its thought occurrence without reinserting the heading or adding an excerpt. Highlight exact text only where it is rendered. If a tool renderer omits or ambiguously transforms matching source, highlight the owning call. Add no new search mode, placeholder, separate preview, or rewritten tool result.

- **Effective renderers and lifecycle.** Resolve the current theme, Markdown environment, and renderer registry after relevant lifecycle changes. Rebind painting and input adapters when Pi replaces its renderer during mode switches. Forward root invalidation to the saved native root once, then invalidate owned geometry and presenters. Do not retain an old extension runner after reload or session replacement.

- **Cleanup.** Release owned timers, subscriptions, search and selection state, mark adapter callbacks inactive, and restore only methods and roots still owned by this adapter. Clear the owned scrollbar's native hiding timer only while the chat root is still owned; do not change a scrollbar retained by a later owner. Restore temporary prototype observations promptly. Release borrowed component references without disposing the native components. Wrappers retained by another owner must become inert after disposal; owned historical presenters follow their own lifecycle. Do not overwrite a later owner's host changes during restoration.

## Testing Decisions

- **Primary seam:** run `pi-chat` inside the real Pi `InteractiveMode` and `AgentSessionRuntime`, loaded through the normal extension loader. Drive scripted provider responses, real tool execution, terminal input, resize, and native lifecycle operations. Record terminal output, clipboard-boundary output, provider requests, and persisted entries. This is one integration boundary for the adapter, occurrence index, disclosure policy, layout, selection, and search together; do not substitute a separately simulated chat host.

- **Reuse existing fixtures.** The repository's native-host fixtures already create a real Pi runtime and session, substitute a recording terminal, and serve controlled responses through an in-process test provider. The composer fixture currently loads the composer implicitly, disables tools, and controls whole responses rather than arbitrary stream stages. Extract only the neutral host setup needed for explicit extension loading, retaining the existing package-specific convenience behavior for its callers. Load `pi-chat` alone by default and opt into composer, attachment, skill-reference, or test extensions for interoperability cases. This fixture is test infrastructure, not a published runtime package or product service.

- **Small fixture extensions.** Allow queued provider scripts to emit thought, text, and tool-call stages, pause, finish, fail, or disconnect. Exercise final-phase evidence through actual provider response formats and Pi's parser. Permit native tools and deterministic test tools through normal extension registration, with controlled progress and results. Allow the native settings and mode changes needed to exercise retries, compaction, and fullscreen transitions. Retain raw protocol bytes and expose fresh complete frames for visual assertions.

- **External assertions.** Assert what a user sees and can operate, what copying produces, what the provider receives, and what the session records. Test through actual input and lifecycle operations, not direct calls into private `pi-chat` reducers or assertions on its index structure. A cumulative stripped terminal log is not a current screen: text visible before a disclosure remains in that log. Use fresh forced frames for visibility assertions, and raw bytes for terminal protocol behavior.

- **Group summary assertions.** Update existing native-host cases to cover active and collapsed wording, fixed segment order, repeated edit paths, a recognized skill read, generic fallback for unknown and historical calls, cleanup, and unchanged expanded tool presentation. Check distinct skill paths and concurrent active calls through the group summary class; add no new test cases for this change.

- **Execution-status and notice corrections.** Update existing native-host cases at the primary integration seam; add no new test cases, files, or seams for this correction. Register deterministic custom-entry renderers through Pi and exercise actual appends, insertion before a streaming assistant, native replay, and user-operated disclosures. ## Out of Scope

- Editing Pi's source, maintaining a Pi fork, replacing its client, or creating an external application, service, terminal installer, or viewer. A requirement that needs a broader implementation must return to discussion.
- A separate transcript-reading overlay, a `/transcript` command, or another navigation view.
- Model verbosity, reasoning effort, model selection, and other model controls. This package changes presentation.
- Planning and todo workflows, subagent workflows, pending-question and recorded-answer workflows, and message actions. Their existing native integrations remain usable; this spec does not build their packages.
- Reimplementing the composer, attachments, skill references, Markdown engine, tool presentation, terminal protocols, image transport, themes, clipboard transport, retries, reconnection, compaction, or agent execution.
- Corrections to `pi-codex-tools`, its execution lifecycle, renderers, metadata, or journals. In particular, no chat-owned reader or compatibility adapter for its earlier standalone execution-status rows, and no new cross-package ownership schema or protocol.
- Classification of unknown or replacement tools by name or renderer output, shell-command parsing, speculative web/integration/visualization/image summaries, tool exclusion lists, patch-specific group exceptions, or a new grouping protocol for tool authors.
- Persistent manual disclosure preferences, embedded source markers, content-based occurrence matching, a duplicated transcript buffer, and a speculative hashing dependency.
- Searching sibling branches, hidden Markdown destinations, or discarded content that is no longer retained; search excerpts or a separate result-preview surface.
- Full disclosure interaction in regular mode, rewriting terminal-owned scrollback, unverified claims of compatibility with arbitrary Pi releases, or lifecycle support for abandoned custom SDK extension discovery.
- A new published UI framework, terminal-specific helper packages, speculative configuration, or performance claims unsupported by measurements.
