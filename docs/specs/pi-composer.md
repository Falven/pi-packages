# Composer specification

## Problem Statement

Preparing a prompt with Markdown, references, and attachments requires reliable selection, correction, and recovery. Users need familiar editing in Pi's terminal interface, and they need other extensions' commands, pickers, and text operations to keep working with that editor. Replacing the editor must preserve configured native operations, including word and line deletion, without losing selections during redraws or treating a terminal-intercepted shortcut as an editor failure. Ghostty can consume otherwise supported Command shortcuts, and selecting a page of a long draft requires editor behavior beyond terminal forwarding.

## Solution

`pi-composer` provides an editable, formatted Markdown draft with a source view, shared undo/redo, ordinary text references, and persistent session drafts. It honors Pi's hardware-cursor setting and renders clickable link text through Pi's terminal capabilities, preserving the terminal's cursor appearance and link-opening gesture. It executes Pi's effective editing actions against that draft and supplies documented convenience shortcuts where input reaches the editor. It extends selection by a visible composer page and offers `/setup-keybinds ghostty` to install eight persistent forwarding rules in one removable configuration block after review and verification. Other composition packages supply paste policy, attachment handling, and inline skill behavior. The supported environment is Ghostty on local macOS in Pi's fullscreen mode.

## Implementation Decisions

- Declare Pi and TUI peers as `^1.0.2`, the supported public API floor.
- Target unmodified, released Pi packages. The attachment integration must not require locally added host APIs or modified Pi builds; revalidate the declared dependency floor rather than assuming a matching version number proves compatibility.
- Markdown text is the authoritative document. Formatted and source views share that document, selection, and undo history. Equivalent Markdown normalization is allowed while preserving meaning, code contents, references, attachment membership, and unformatted source constructs.
- The composer owns caret movement, selection, text transactions, draft attachment membership, and session draft persistence. Paste policy, stored attachment contents, and their lifetime belong to `pi-attachments`; inline skill completion and expansion belong to `pi-skill-references`.
- Attachment membership follows ordinary Markdown attachment references in the draft. A user operation that changes those references commits as one text transaction, so undo and redo restore text and membership together. Moving a caret or switching views does not create an independent content edit; a fresh edit after undo follows ordinary redo-branch semantics.
- Draft identity, targeted replacement, and history coordination required by attachment capture belong to the composer package. Keep Pi's native editor and submission callback signatures intact; additional cooperation between the two packages is not an official Pi API. Preserve the actual requesting draft through pending capture, history recall, and submission without inferring identity from equal text. The separately scoped native-editor adapter is conditional on its own compatibility experiment; composer checks do not establish equivalent native-editor capabilities. Preserve the selected editor and keep the composer optional.
- Keyboard and mouse selection target the same source ranges. Typing, insertion, and paste replace the selection and preserve tab characters. Movement and rendering respect grapheme boundaries, wrapped lines, and terminal cell widths. Redraw, resize, scrolling, view changes, and attachment-preview updates preserve the range and anchor; they do not create an edit or clear selection.
- Copy and cut export plain Markdown text through Pi's clipboard support. Cutting must preserve the selected content if copying fails. Pasting copied references preserves their text; canonical skill syntax retains its invocation meaning.
- Empty native insertion or paste leaves the draft and selection intact. Deletion at a source boundary with no selected or adjacent text is a no-op and does not invalidate a pending clipboard insertion. Cut remains an explicit deletion after a successful copy.
- Clipboard paste invokes the supplied native handler and preserves its chosen insertion route. Pi's default handler returns failed or unavailable text reads as empty results and delivers copied-file or temporary image paths as strings. The standalone composer can retain only delivered content; `pi-attachments` supplies metadata-aware capture, read-error reporting, and stable snapshots. The composer guards late results delivered to its own editors, but cannot recover a handler's unexposed payload or guard an unrelated replacement editor.
- Clipboard-manager files and images use the effective native clipboard action, Ctrl+V by default on macOS, after the selected item is copied to the system clipboard. With `pi-attachments`, copied files and single-path text pastes become snapshots when readable, and captured images get previews. Classification depends on the supplied payload regardless of caret position. Create from text… captures literal entered characters, and Restore Inline converts an existing text attachment to editable draft content; no Paste Inline action is retained. A raw Cmd+V reaches the clipboard handler only when the terminal forwards it and Pi's native dispatch leaves it available; terminal-delivered paste uses the same text policy without rereading the clipboard.
- Resolve native editing actions through the keybinding manager supplied to the editor factory. Execute them against the authoritative draft and history; the inherited editor's private document cannot perform these edits. Use public user-binding information to detect explicit overrides. Pi owns decoding, protocol negotiation, configuration, and application dispatch; the composer adds no parallel manager or configuration reader.
- Native submit and newline actions use their effective bindings. With defaults, Enter submits ordinary prose and continues lists or code where the caret is editing that structure; Shift+Enter inserts a newline. The Cmd+Enter alias submits explicitly from prose, lists, and code when available. In-editor completion acceptance handles its keys before contextual submission; native undo retains its earlier priority. Preserve native command, steer, and follow-up dispatch.
- Live formatting covers paragraphs, headings, bold, italic, strikethrough, links, quotes, lists, task lists, inline code, fenced code, and horizontal rules. Source-to-cell mapping must let users edit the underlying text without losing syntax or code contents.
- Reuse Pi's exported Markdown parser, themes, highlighting, rendering utilities, Unicode utilities, and scrolling facilities.
- Read hardware-cursor visibility from the supplied TUI on each render. The focused composer always emits Pi's cursor-position marker. When Show hardware cursor is enabled, Pi displays the terminal cursor and the composer omits its drawn caret; otherwise the composer draws its usual inverted caret. Selection highlighting remains independent, including when the caret is within a selected range. Cursor appearance and blinking follow terminal preferences, and focus, scrolling, resize, and view changes retain native positioning.
- Carry the Markdown parser's link destinations through source-to-cell projection. Render recognized plain URLs, autolinks, inline links, and reference-style link labels with Pi's hyperlink helper when its effective capabilities enable hyperlinks. Retain link metadata through nested formatting, lists, quotes, wrapping, and Unicode cells. Source view displays literal Markdown while retaining hyperlinks on recognized link text; formatted view displays the linked label. Code contents retain their literal presentation.
- Hyperlink control sequences belong only to rendered output. They never enter draft text, clipboard text, undo history, persistence, or submitted Markdown. Empty destinations or destinations containing control characters produce ordinary editable text without a hyperlink. Link spans close before adjacent text, row boundaries, and the end-of-line caret, so redraws and wrapping cannot make unrelated content clickable. Disabling native hyperlink capability retains the same visible text and editing behavior.
- Convert absolute local Markdown destinations, including attachment references, to properly encoded file URLs for rendered hyperlinks. Local file URLs use an explicit localhost authority for terminal activation. Preserve existing URL encoding and nonlocal URL authorities; the draft, copied text, and submitted references retain their original destinations. The composer does not read or copy linked files, and opening follows the system's associated application and ordinary file semantics.
- The terminal handles link activation using its native gesture; ordinary composer clicks and drags retain caret positioning and selection. In Ghostty fullscreen mode on macOS, use Shift+Cmd+click. Hover feedback follows Ghostty's behavior while Pi captures mouse input. Neither cursor display nor link rendering modifies terminal settings.
- Implement the public `EditorComponent` contract, preserving host callbacks, autocomplete updates, and application actions. `getEditorText`, `setEditorText`, `pasteToEditor`, insertion, and external-editor actions must reach the same state owner. Native text replacement is distinct from paste classification.
- Consume the effective `AutocompleteProvider` supplied by Pi, including later updates. Preserve cancellation, suggestion results, completion edits, cursor positions, and native `SelectList` behavior. Extension-owned pickers continue to insert text through native interfaces. Provider composition does not imply a public hook for replacing every in-editor picker renderer.
- Native `@` file and directory completion retains effective filtering, quoting, and directory navigation. References stay character-editable. File references identify current source files; attachment references identify preserved contents.
- Autosave each session's draft text and attachment references with native session identity and persistence facilities. Restore those drafts across switches and restarts. A failed save preserves recovery content and cancels a session switch or fork; content held only in process memory requires a successful retry before exit. Keep undo/redo in memory and isolated by session; a restarted process begins with a fresh history.
- Retain the association between an asynchronous operation and its requesting draft. Later results must preserve unrelated edits and remain recoverable when the original insertion can no longer be applied safely.
- Derive recovery filenames from session identity without interpreting that identity as a filesystem path. Imported session metadata cannot redirect clipboard recovery outside package-owned storage.
- Limit formatted replacement work to Markdown elements intersecting the edit. Character deletion locates source grapheme boundaries without constructing a second whole-document projection. Preserve formatting, selection, Unicode, and undo behavior through both paths.
- Retain cleared drafts in individual native session entries rather than repeating their full contents in every appended checkpoint. The replaceable disk recovery file keeps a complete snapshot. Existing checkpoints remain readable; save failures and partially completed checkpoint sequences preserve retryable content.
- Use Pi's host submission path, input transformations, commands, and steer/follow-up behavior. The attachment compatibility experiment must test delaying one Send before editor clearing until already-running capture and required image preparation finish. Submit the original request with retained references while preserving later edits, undo/history, recovery, and its original normal, steering, or follow-up intent; later same-route text must not overtake that image because of attachment preparation. Do not require another Send or replay Enter against a newer draft. The integration is verified separately for the native editor and composer through the existing public host checks; it may not change Pi's source or private queue. Draft clearing and recovery must follow actual host lifecycle outcomes. The text-only submission callback and void-returning send API do not constitute acknowledgement.
- Use Pi's fullscreen layout, mouse routing, terminal decoding, and extension UI facilities. Respect Pi's single active editor and existing override behavior. Document physical delivery separately from editor actions. Loading the package and ordinary editing leave terminal settings unchanged; explicit setup follows the configuration contract below. A terminal-consumed key cannot be recovered by the composer or shell.
- Load the composer before editor decorators. Later decorators preserve the existing factory's public methods and callback assignments; paste and attachment decorators support either order. A later replacement editor becomes Pi's active editor under the native single-editor contract.

### Native editing behavior

A line is a logical line separated by a newline. A visual row is a displayed row after wrapping. Line actions target logical source boundaries, including leading and trailing Markdown syntax; document boundaries are the beginning and end of the source. Vertical movement follows visual rows and preserves the preferred display column where possible. Formatted view maps source positions to terminal cells.

| Native action                                                                 | Required behavior                                                                                                                                                                                                                                                                                      |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `tui.editor.deleteCharBackward` / `deleteCharForward`                         | Remove the selection or one whole grapheme in the requested direction. Preserve native newline joining.                                                                                                                                                                                                |
| `tui.editor.deleteWordBackward` / `deleteWordForward`                         | Remove the selection or the native word range, retaining the removed Markdown for yank. At the corresponding logical boundary, remove the newline and join adjacent lines.                                                                                                                             |
| `tui.editor.deleteToLineStart` / `deleteToLineEnd`                            | Remove the selection or text toward the logical line boundary. At that boundary, remove the adjacent newline when present. Retain removed Markdown for yank.                                                                                                                                           |
| `tui.editor.yank` / `yankPop`                                                 | Insert the latest retained deletion at the caret or over the selection. Yank-pop rotates retained entries by replacing the preceding yank or yank-pop; it is inactive after unrelated editing or movement.                                                                                             |
| `tui.editor.cursorLeft` / `cursorRight`, `cursorWordLeft` / `cursorWordRight` | Move by grapheme or native word boundaries in the shared draft. Use the shared source selection and keep its original anchor for Shift movement.                                                                                                                                                       |
| `tui.editor.cursorLineStart` / `cursorLineEnd`                                | Reach the current logical line's beginning or end in either view.                                                                                                                                                                                                                                      |
| `tui.editor.cursorUp` / `cursorDown`                                          | Move through visual rows. In an ordinary draft, an extra Up on the first row reaches its beginning; an extra Down on the last row reaches its end.                                                                                                                                                     |
| `tui.editor.historyPrevious` / `historyNext`                                  | Browse native prompt history through the shared draft. Preserve explicit history bindings, empty-editor behavior, and active history browsing. Unmodified Up can enter history once the caret is already at the draft's beginning; Shift movement never does.                                          |
| `tui.editor.jumpForward` / `jumpBackward`                                     | Await a printable target and move to its next/previous occurrence, searching across logical lines; no match leaves the caret unchanged. A repeated jump key cancels, and other control input cancels then follows native dispatch. Keep grapheme boundaries and map visible targets in formatted view. |
| `tui.editor.pageUp` / `pageDown`                                              | When delivered, move by one visible composer page and retain the preferred column. Shift selection derived from the effective binding keeps its anchor and extends the source range. Pi's fullscreen viewport retains keys it handles before the editor.                                               |
| `tui.editor.undo`                                                             | Restore the prior coherent draft edit and selection, including attachment membership, before in-editor autocomplete handling.                                                                                                                                                                          |

All deletion actions consume a nonempty selection before computing an unselected range. A deletion at an outer boundary with no text to remove is a no-op. Consecutive native word/line deletions accumulate retained text in source order: backward deletions prepend and forward deletions append. An intervening edit or movement ends accumulation. Yank and yank-pop use the composer's same document and undo history.

Both views delete the same literal source range for a given caret or selection. Character, word, and line deletion include hidden Markdown characters and follow Pi's ordinary grapheme, punctuation, whitespace, and newline boundaries. Selection deletion removes exactly the selected source, including any syntax inside that range. Retained text is exactly the deleted source; yank restores it in source order, and undo restores the prior text, selection, and attachment membership.

After each edit, the existing Markdown parser determines the presentation from the resulting source. Valid syntax renders immediately, and incomplete syntax follows the parser's normal handling of literal text and any remaining valid formatting. This applies to every rendered construct, including nested formatting, links, attachment references, lists, and code. An attachment reference remains active only while the resulting text is recognized by the attachment package; editing does not change its retained file contents.

### Binding and dispatch

Preserve the native input path in this order:

1. Terminal-input listeners, fullscreen viewport handling, overlays, and focused components keep the input the host routes to them.
2. Extension shortcuts accepted by Pi retain its conflict rules. Native clipboard, context-sensitive interrupt/exit, explicit history bindings, and other application actions keep their native precedence.
3. At the editor, native undo precedes in-editor autocomplete. Picker navigation, acceptance, and cancellation retain their native priority over ordinary editor fallbacks.
4. Effective native editing bindings resolve before composer convenience or fixed shortcuts. A native deletion action assigned to Cmd+A deletes once; it does not also select all.
5. A composer alias for a native action is available only when that action has no explicit binding override. Changing its binding or setting an empty list suppresses all its aliases, including Shift variants. An explicit binding that repeats a default still counts as an override.

For Shift selection, resolve any effective action on the full chord first. Otherwise extend using the effective movement binding or an available movement alias, keeping the original anchor. Do not derive selection keys from suppressed aliases. Option+Up/Down retain Pi's effective application behavior, including its default dequeue action on Option+Up.

| Composer key                           | Action/configuration contract                                                                                                                                      |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Cmd+Left; Shift variant                | Alias for `tui.editor.cursorLineStart`; target the current logical line.                                                                                           |
| Cmd+Right; Shift variant               | Alias for `tui.editor.cursorLineEnd`; target the current logical line.                                                                                             |
| Cmd+Up/Down; Shift variants            | Fixed movement to the draft's beginning/end, or selection to that boundary. No native action IDs exist; yield to effective native and accepted extension bindings. |
| Cmd+C                                  | Alias for `tui.input.copy` when native dispatch delivers it to the editor; preserve parent interrupt/clear behavior.                                               |
| Cmd+V                                  | Alias for the effective `app.clipboard.pasteImage` route; preserve its supplied handler and paste policy.                                                          |
| Cmd+Z                                  | Alias for `tui.editor.undo`.                                                                                                                                       |
| Cmd+Enter                              | Alias for `tui.input.submit`, requesting explicit submission after higher-priority handlers.                                                                       |
| Cmd+A, Cmd+X, Cmd+Shift+Z, Cmd+Shift+M | Fixed select-all, cut, redo, and source-view actions. These have no configurable native action IDs and yield to effective native and accepted extension bindings.  |

Existing native movement, deletion, history, recovery, newline, and submit actions remain configurable through Pi. Changing or clearing native line actions suppresses Cmd+Left/Right aliases without disabling the independent Cmd+Up/Down draft shortcuts. A terminal translation such as Cmd+Delete producing Ctrl+U follows whichever native action currently owns Ctrl+U. Suppressing a raw Cmd+V alias does not disable terminal-generated bracketed paste. Each input performs at most one operation.

Draft-boundary movement targets the first or last editable position in the active view. Shift preserves the original anchor across repeated gestures and direction changes. Movement at a draft boundary stays in the draft and creates no undo entry.

Fixed shortcuts are package behavior. Pi's current public manager cannot register new configurable action IDs; literal extension shortcut registration does not change that. Native `/hotkeys` describes host actions and registered extension shortcuts, while this specification documents the direct composer aliases. Neither Pi nor the composer automatically imports macOS text-field settings.

### Page selection

Derive selection gestures by adding Shift to each effective native page-movement binding after resolving any action that owns the full chord. With default bindings, Shift+PageUp/PageDown extend selection; on the target Mac keyboard these are Shift+Fn+Up/Down. Explicit remapping or clearing changes the available derived gestures. A chord explicitly assigned to a native action executes that action with its ordinary behavior, even when the chord contains Shift.

Move the selection head by the number of visual rows in the current visible composer page, retaining the original anchor and preferred display column. Count editable composer rows rather than the terminal's total height or scrollback. Use the existing projection for wrapped rows, hidden Markdown syntax, tabs, and whole graphemes. Clamp to an available row and valid position when a full page is unavailable; never browse prompt history from a selection gesture.

Repeated gestures extend the same range and opposite gestures contract it before extending in the other direction. Redraw, resize, source/formatted view changes, and attachment-preview refresh preserve the source selection. Paging alone creates no content edit; replacement, cut, paste, and undo continue through the existing draft history. Pi's fullscreen viewport, focused native UI, and accepted extension shortcuts retain their earlier dispatch priority.

### Ghostty keybinding setup

Register `setup-keybinds` through Pi's public command API with the description "Review, install, or remove persistent terminal keybindings". Usage is `/setup-keybinds <terminal> [remove]`; list `ghostty` as the supported terminal. `/setup-keybinds ghostty` reviews and installs the block; `/setup-keybinds ghostty remove` reviews and removes it. Missing or unsupported arguments produce usage information without a write. Use native confirmation and notification facilities; without interactive confirmation the command cannot modify configuration. Pi retains normal command dispatch. From the start of its handler, setup preserves the draft, selection, history, and editor ownership; closing its native dialog restores editor focus without an additional edit or model submission.

Before confirmation, show the resolved target file, the eight affected shortcuts, and the fact that forwarding remains active outside Pi until removal and configuration reload. Existing Pi overrides still determine which action receives each chord. Installation leaves working Cmd+C and Cmd+Shift+Up/Down bindings intact and does not edit Pi's keybinding configuration. Ghostty's Cmd+V and terminal menu paste remain unchanged; `pi-attachments` handles delivered single-path text and Pi's configured native clipboard action.

The block contains exactly these forwarding rules. CSI payloads omit the escape-plus-left-bracket prefix, which Ghostty's native CSI action supplies.

| Physical gesture | Ghostty trigger    | CSI payload | Default composer behavior after delivery             |
| ---------------- | ------------------ | ----------- | ---------------------------------------------------- |
| Cmd+A            | `super+a`          | `97;9u`     | Select the entire draft and retain the selection.    |
| Cmd+Enter        | `super+enter`      | `13;9u`     | Submit explicitly after higher-priority handlers.    |

Use one block delimited by the comments `BEGIN pi-composer keybindings` and `END pi-composer keybindings`, appended to the existing configuration. Preserve surrounding contents and file permissions. Create no backups. Repeated setup with the intact block performs no write; report an ineffective block instead of duplicating it. An edited, incomplete, or duplicated block requires manual resolution. Removing an absent block is a no-op; removing an intact block deletes only its managed contents and preserves unrelated later edits. Appending and removing the block must preserve the original surrounding bytes, including existing line endings and the final-newline state.

Resolve the configuration Ghostty loads within the supported boundary below. A missing or ambiguous target, invalid configuration, include, unavailable Ghostty verification, or unsupported configuration leaves live settings unchanged. Report the conflicting shortcut and source when established; report an inability to verify when that is the actual limitation.

Before installation, use Ghostty to validate the proposed configuration and establish the eight resulting effective bindings without changing live settings. Removal validates the remaining configuration. Refuse files with ACL permissions, including staged candidates; preserve the ordinary owner, group, and mode. Recheck the reviewed contents, permissions, and configuration context before atomic replacement. Success is reported only after the intended contents have been written; give the native reload instruction after installation or removal. Package reload, Pi exit, and returning to the shell do not remove an explicitly installed block.

#### Verification boundary

Setup supports Ghostty 1.3.1 on local macOS with exactly one existing regular, user-owned Application Support configuration, using either `config` or `config.ghostty`. XDG configuration files, multiple default configurations, includes, and extra Ghostty launch arguments prevent a write. Pi's process ancestry must identify a Ghostty process owned by the same user, with matching executable, account home, and configuration roots. Root-owned intermediate processes, including macOS's login process, do not invalidate that same-user match.

The system Python 3 runtime supplies read-only native process and keyboard context. The Darwin process query is an unstable platform interface; an unavailable runtime, denied query, unexpected result, or context mismatch reports verification unavailable and leaves live settings unchanged.

Installation and repeat verification require the selected keyboard input source and underlying layout to both identify `com.apple.keylayout.US`. Native configuration and binding inspection must show no modifier remapping and no higher-priority physical bindings for Cmd+A, Cmd+Z, or Cmd+Shift+Z, including sequence starters. Default physical digit bindings remain compatible with this layout. Removal does not require these installation-only keyboard checks, so layout or binding changes cannot prevent removing an intact block.

Within that verified single-source context, Ghostty validates the exact staged candidate and its last-binding-wins behavior establishes the eight appended rules. Fresh native configuration and binding inspection establishes the baseline and detects conflicts; it is not a query of the proposed candidate or the GUI's currently loaded state. Unsupported configurations receive no live write. The user reloads Ghostty after installation or removal; file validation alone does not establish physical shortcut delivery.
